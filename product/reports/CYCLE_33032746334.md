# Cycle 33032746334 — Product Lane

## Hypothesis
The product needs "understandable explanations of proximity" (per the product directive) and language-aware controls to address the evaluation finding that the baseline is FALSIFIED (language dominance 0.982). Adding proximity explanations, cluster coherence indicators, and language filtering will make the map genuinely useful for jurists who need to understand WHY decisions are near each other.

## What was built

### 1. Proximity Explanation Engine (`product/app/proximity_explainer.py`)
New module that decomposes neighbor proximity into 6 interpretable features:
- **Language** (0.15 weight) — intentionally downweighted from the 0.982 dominance
- **Branch** (0.25 weight) — legal branch is more important than language
- **Legal area** (0.20 weight)
- **Citation overlap** (0.20 weight) — Jaccard similarity over cited decisions + laws
- **Text length** (0.05 weight)
- **Date proximity** (0.15 weight)

Returns structured explanations with:
- Feature-level contributions (which features drove proximity)
- Warnings (e.g., "proximity driven primarily by language match")
- Suggested alternative views (e.g., "try erwaegungen mode")
- Human-readable summary

### 2. Cluster Coherence Analysis (`product/app/navigation.py`)
New `get_cluster_coherence()` method computes:
- Language distribution per cluster (via Counter)
- Branch distribution per cluster
- Legal area distribution per cluster
- Purity score (0-1, higher = more homogeneous)
- Coherence warnings (e.g., "cluster dominated by single language")

Key finding: 10 of 11 clusters at zoom 1 are dominated by a single language. This confirms the evaluation finding that the baseline groups by language, not legal content.

### 3. Language-Aware Map Filtering (`product/app/navigation.py`)
New `get_map_data_with_language_filter()` method:
- Returns all positions but marks filtered-out ones with `filtered_out: true`
- Frontend shows filtered positions as dimmed dots
- Language toggle buttons (de/fr/it) in sidebar

### 4. Frontend Updates (`product/static/index.html`)
- **Language filter toggle** — de/fr/it buttons with color-coded dots
- **Language-colored map points** — outer ring = language color, inner fill = cluster color
- **Language badges in tooltips** — color-coded language indicator
- **Cluster coherence indicators** — language/branch distribution bars in sidebar cards
- **Proximity explanation panel** — shown in decision detail when viewing neighbors
- **Keyboard shortcuts** — 1-4 for zoom, Esc to close panel
- **Language-filtered hover** — only hover over visible (non-filtered) points

### 5. API Endpoints
- `GET /api/proximity?id_a=...&id_b=...` — proximity explanation
- `GET /api/cluster_coherence?representation=...&zoom=...&cluster_id=...` — cluster analysis

## Key findings
1. **Language dominance confirmed**: 10/11 clusters are dominated by a single language. Cluster 7 (65 decisions) is the only mixed-language cluster with purity 0.456.
2. **Proximity explanations work**: Cross-branch same-language pairs correctly trigger warnings about language-driven proximity.
3. **Language filter effective**: Filtering to German only shows 605/1000 positions, hiding 395 French/Italian decisions.
4. **Feature weights validated**: Language (0.15) is intentionally weighted less than branch (0.25) and legal_area (0.20).
