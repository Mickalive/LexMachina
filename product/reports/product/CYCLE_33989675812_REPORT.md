## Features Implemented

### FEAT-078: TF-IDF Truncation Fix

**Problem:** TF-IDF model was built from `full_text` truncated to 2000 chars
by `Decision.to_full()`, losing 70-95% of document content for typical Swiss
Federal Supreme Court decisions (avg 15,000-50,000+ chars).

**Fix:**
- Added `Decision.to_full_raw()` — returns untruncated `asdict()` output
- Added `CorpusLoader.get_all_decisions_raw()` — returns all decisions with
  untruncated text
- Updated `NavigationAPI.initialize()` to build TF-IDF from raw untruncated text
- Raised `to_full()` API response limit from 2000 to 8000 chars

**Impact:** TF-IDF proximity calculations now use complete document text,
improving text similarity accuracy for decisions with rich legal content
beyond the first 2000 characters.

### FEAT-079: Temporal-Filtering Metadata Gap Fix

**Problem:** Temporal filtering fallback path checked only `meta.get("decision_date")`
but map metadata stores year as `meta.get("year")`, causing decisions
outside the corpus to silently bypass temporal filtering.

**Fix:** Updated `get_temporal_map_data()` to fall back to `meta.get("year")`
when `decision_date` is unavailable:
```python
meta.get("decision_date", meta.get("year", ""))
```

**Impact:** Forward-compatible with 174k corpus scale-up where map decisions
may not all be in the corpus.

### FEAT-080: Cross-Language TF-IDF Text Similarity Neighbors

**Problem:** Cross-language neighbor discovery returned empty results for all
decisions because 2D map geometry is dominated by language (0.982 dominance),
placing same-language decisions in spatial proximity.

**Fix:**
- Added `LanguageAnalyzer.find_cross_language_neighbors_by_text()` — uses
  TF-IDF cosine similarity to rank cross-language candidates by legal
  content similarity rather than spatial proximity
- Updated `NavigationAPI.get_cross_language_neighbors()` to return both
  methods: spatial (baseline) and text-similarity (language-invariant)
- Updated frontend to display both neighbor types with appropriate labels

**Impact:** Jurists can now discover cross-language decisions with similar
legal content, enabling navigation across language boundaries for the first
time.

### FEAT-081: Jurist-Feedback Loop Closure

**Problem:** Feedback system was write-only — jurists could submit feedback
but nothing read it back. No individual record retrieval, no cluster quality
surfacing, no export for analysis.

**Fix:**
- Added `NavigationAPI.get_feedback_records()` — paginated record retrieval
  with optional type filter
- Added `NavigationAPI.get_cluster_feedback_summary()` — aggregated
  cluster quality ratings for surfacing as badges/tooltips
- Added `NavigationAPI.export_feedback()` — JSON/CSV export for analysis
- Three new server endpoints:
  - `GET /api/feedback/records?limit=&offset=&type=`
  - `GET /api/feedback/clusters?cluster_id=`
  - `GET /api/feedback/export?format=json|csv`

**Impact:** Feedback loop is now closed — records are retrievable, cluster
quality ratings can surface on the map, and data can be exported for
evaluation-lane analysis.
