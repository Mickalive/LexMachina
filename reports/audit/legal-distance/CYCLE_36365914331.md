**Implication**: The embeddings were computed in a different environment (likely a prior runner with the full corpus mounted) and the results were staged into the producer workspace. The audit cannot verify the *exact* input texts used for 2024.

**Mitigating evidence**:
- The accepted base (2000-2023) has identical checkpoint structure and was previously audited

- The computation script is deterministic (fixed model, batch_size=128, no randomness in encoding)
- Cross-year consistency metrics (mean embedding cosine similarity 0.9988) are too high for independently computed dummy data

**Assessment**: While the provenance chain has a gap (missing input corpus verification), the output consistency with previously validated years provides strong circumstantial evidence of correct computation. This is a **documented limitation**, not a blocking defect.

**Claim**: The directory is named `174k_dense_embeddings` and the script comments reference "174k corpus" and "173,963 entries".

**Reality**: **165,463 decisions** across 2000-2024 (158,427 for 2000-2023).

**Explanation**: The "174k" figure likely includes:
- Decisions from years before 2000 (excluded by product scope)
- BGE (published) decisions in addition to bger (unpublished)
- Or an earlier estimate that wasn't updated

**Assessment**: This is a **naming/documentation issue**, not a computation defect. The actual count (165k) is internally consistent. The control plane correctly states "174k-scale" as an approximate target.
