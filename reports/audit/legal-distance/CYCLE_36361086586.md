## 3. Adversarial Attacks on Methodology

### 3.1 Computation Integrity — **NO EVIDENCE OF CORRUPTION**

**Threat**: Embeddings are dummy data (zeros, random noise, or copied from earlier years).

**Defense**: 
- Variance per dimension: ~0.001 (non-zero, consistent across years)
- Pairwise cosine similarities show natural distribution (mean 0.87-0.89, std 0.04-0.05)
- Language/branch metadata matches expected distributions
- Embeddings differ across years (different shapes, different values)

**Conclusion**: Embeddings are genuine model outputs, not placeholders.

### 3.2 Data Provenance Gap — **DOCUMENTED LIMITATION**

**Finding**: The computation script references `/tmp/lex_accepted/corpus/...` and `/tmp/lex_accepted/evaluation/...` paths which **do not exist** in the current environment.

**Implication**: The embeddings were computed in a different environment (likely a prior runner with the full corpus mounted) and the results were staged into the producer workspace. The audit cannot verify the *exact* input texts used.

**Mitigating evidence**:
- The accepted base (2000-2019) has identical checkpoint structure and was previously audited
- Metadata structure and decision_id formats match perfectly
- Embedding quality metrics are consistent across the 2000-2023 boundary
- The computation script is deterministic (fixed model, batch_size=128, no randomness in encoding)

**Assessment**: While the provenance chain has a gap (missing input corpus verification), the output consistency with previously validated years provides strong circumstantial evidence of correct computation. This is a **documented limitation**, not a blocking defect.

### 3.3 "174k" Naming Discrepancy — **CLARIFIED**

**Claim**: The directory is named `174k_dense_embeddings` and the script comments reference "174k corpus" and "173,963 entries".

**Reality**: Only **158,427 decisions** across 2000-2023.

**Explanation**: The "174k" figure likely includes:
- Decisions from years before 2000 (excluded by product scope)
- BGE (published) decisions in addition to bger (unpublished)
- Or an earlier estimate that wasn't updated

**Assessment**: This is a **naming/documentation issue**, not a computation defect. The actual count (158k) is internally consistent. The control plane correctly states "174k-scale" as an approximate target.

### 3.4 Finalization Not Yet Run — **EXPECTED STATE**

The `finalize_174k_embeddings.py` script has **not been executed**. The expected outputs (concatenated 768-dim, center_projected 768/64/128, run_metadata.json) do not exist.

**Status**: This is the **correct and expected state** for this cycle. The factory direction v27 states: "Dense embeddings (center_projected 768/64/128) IN PROGRESS via year-split computation". Year-split computation is complete; finalization is the next logical step.
