## 2. Findings

### F1 — Material: coarse-level ARI omitted from the claim-bearing verdict/report (selective metric use)
`r3_source_isolation_results.json` contains `coarse_ARI_branch` = **0.258 / 0.175 / 0.163**. Neither `r3_source_isolation_verdict_v1.json` nor `FRACTAL_MAP_V35_OPERATIONAL_RESUME_38048724922_20261010.md` reports it. Both instead use the **fine-level** `ARI_branch ≈ 0.04` (with 365–1316 fine clusters) to assert the hierarchy "do[es] not recapture the coarse 5-class human **branch** axis". Using a fine-granularity ARI to characterise a *coarse* claim is invalid: the correct coarse-level measure shows weak-to-moderate recapture (0.16–0.26), not ~0.04. The verdict does report the fine ARI and the product coarse ARI (0.00024) but suppresses the R3 coarse ARI that sits between them. This is selective reporting of a method-available metric in a claim-bearing artifact.

### F2 — Material: frozen parent positive control still fails; the harness remains INVALID
The frozen `EVAL_SPEC_FROZEN.json` (agreement harness) rule states: *"full_text_tfidf_light (full 173,963) must show ARI_branch > 0.05; if not, the whole evaluation harness is invalid and no claim is made"*, and `harness_verdict` = **INCONCLUSIVE_POSITIVE_CONTROL_FAILED**. The producer attributes the discrepancy **entirely** to the product join defect ("Discrepancy is NOT scientific — it is a product join/alignment defect"). But the source-corrected R3 run on the *evaluation-v25* embeddings still yields full_text `ARI_branch = 0.0429 < 0.05`, i.e. the positive control fails even after removing the join defect. The harness is thus still invalid under its own frozen rule, and the correct reading is *both* a product defect *and* a genuine failure of the metric to demonstrate branch recovery. The verdict/report instead frame the accepted headline as an unqualified "CONFIRMED" and never reconcile this. The R3 spec's `ARI_branch < 0.10` threshold is the `recovers_branch` rule, not the positive-control rule; using the wrong frozen threshold to declare the outcome "CONFIRMED" overstates the evidence.

### F3 — Material: producer state contradicts itself on product/serving status
`state/fractal-map.json` has `continue_recommended=False`, `cycle_status=COMPLETE_FALSIFICATION_PRODUCT_JOIN_BLOCKER`, yet its top-level `next_recommendation` still asserts the modes are "FINALIZED and OPERATIONAL" and `critical_findings` contains "Accepted headline CONFIRMED" while the same object documents the product artifacts as scrambled. Downstream automated consumers (notably the product lane, which reads this state) can read the top-level field as an endorsement of artifacts this very cycle declared untrustworthy.

### F4 — Minor: provenance/timestamp inconsistency
`r3_source_isolation_verdict_v1.json` `created_utc = 2026-10-10T12:45:00Z` postdates the containing commit `c431c1ee` at `2026-10-10 12:35:28Z`.
