### ❌ REQUIRES CORRECTION — Factual Inaccuracies

#### 1. 144k Checkpoint `strict_nesting` Claim (State File & Operational Resume)

**Claim:** "strict_nesting ≥0.99" (state file `key_findings.144k_checkpoint_dense_validation`, operational resume table)

**Actual Data:** Three configs tested at 144k:
- `coarse_0.5_fixed2.0_min20`: `strict_nesting: 1.0` ✅
- `coarse_0.5_fixed3.0_min20`: `strict_nesting: 0.9892367906066536` ❌ (< 0.99)
- `coarse_0.25_fixed2.0_min20`: `strict_nesting: 0.998468606431853` ✅

**Impact:** One of three configs fails the ≥0.99 threshold. Claim should be qualified: "strict_nesting ≥0.99 for 2/3 configs; one config at 0.989."

#### 2. 144k `branch_improvement` / `hier_impr` Misattribution (Operational Resume)

**Claim:** "28k/144k checkpoints validate dense extrapolation (hier_impr ~0.67, fine_branch_purity ~0.97)"

**Actual Data:**
- 28k checkpoint: `hier_impr ~0.67` (improvement_rate=0.667) — **correctly attributed to 28k**
- 144k checkpoint: `branch_improvement: 0.052–0.092` (config-dependent), `zoom_branch.improvement_rate: 0.48–0.52`

**Impact:** The ~0.67 value is from 28k, not 144k. The 144k branch improvement is substantially lower (0.05–0.09). Operational resume conflates the two scales.

#### 3. 144k `zoom_branch` Improvement Rate Range (Operational Resume)

**Claim:** "zoom improvement_rate 0.48–0.65 branch / 0.75–0.76 area"

**Actual Data (144k):**
| Config | zoom_branch.improvement_rate | zoom_area.improvement_rate |
|--------|------------------------------|----------------------------|
| coarse_0.5_fixed2.0_min20 | 0.52 | 0.76 |
| coarse_0.5_fixed3.0_min20 | 0.48 | 0.76 |
| coarse_0.25_fixed2.0_min20 | 0.65 | 0.75 |

**Impact:** The 0.65 branch rate only appears in the coarse_0.25 config. The production config (coarse_0.5_fixed2.0_min20) shows 0.52. Claim should specify config dependence.

#### 4. 12k Dense hierarchical_v1 Failure Reason (State File `negative_results`)

**Claim:** "Dense embeddings at 12k ACCEPTED FAIL frozen hierarchical_v1 protocol (singleton_fraction 2.9–5.0% > 1% threshold) — different protocol than 28k/144k checkpoint validation"

**Actual Data:** `v26_12k_dense_verdict.json` shows failure on `improvement_rate_gt_0.5_on_2_of_4: false` (v26 zoom-quality rule), NOT on singleton_fraction. The v26 test checks monotonic purity improvement across 4 resolution transitions; the frozen hierarchical_v1 protocol checks `nesting≥0.99 AND fine_branch_purity>0.5 AND improvement_rate>0.5 AND singleton_fraction<0.01`. These are **different protocols**. The state file incorrectly attributes the v26 failure to hierarchical_v1 singleton threshold.

**Impact:** Misrepresents which protocol failed and why. The 12k dense embeddings have not been evaluated under the frozen hierarchical_v1 protocol; they were evaluated under v26 zoom-quality rule (which they fail as expected due to scale dependency).
