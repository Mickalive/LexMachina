## Finding Details

### Finding 1: Report Table Source Mixing (Non-blocking)

Section 2.4 of the debiasing report presents a comparison table with three columns:

| Representation | Legal Purity | Source |
|---------------|-------------|--------|
| Full Text TF-IDF | 0.324 | Individual experiment (resolution 1.0, `min_df=1`) |
| Erwägungen TF-IDF | 0.385 | Close to both sources (individual: 0.3836, unified: 0.3848) |
| S+E TF-IDF | 0.344 | **Unified evaluation only** (resolution 1.0, `min_df=2`, 857 decisions) |

The individual experiment shows S+E legal_purity = 0.3766, not 0.344. The report uses the unified evaluation value (0.344) without disclosing this. The unified value is arguably more methodologically sound (common decision subset, consistent min_df), but the mixing of sources without disclosure is a documentation clarity issue.

**Impact:** None on scientific findings. The unified evaluation values are defensible. The report should note which source each value comes from.

### Finding 2: NMI Range Rounding (Non-blocking)

The report claims debiased NMI range is "0.86-0.90" but the actual computed range is 0.858-0.898. Rounding the lower bound upward from 0.858 to 0.86 is technically inaccurate (the true minimum is below the stated floor). The rounded range "0.86-0.90" is used in the state file and repair report.

**Impact:** Marginal. The actual value 0.858 is very close to 0.86 and both support the hierarchy consistency claim. However, audit precision should prefer exact values.

### Finding 3: float64 dtype Inconsistency (Non-blocking)

`embeddings_graph_only.npy` has dtype float64 while all other embeddings (including `embeddings_blended.npy` from the same experiment) use float32. Caused by `np.zeros()` default dtype in `citation_embeddings.py` line 243.

**Impact:** None on scientific findings. Leiden normalizes embeddings before clustering. The file is 2x larger than necessary (512KB vs 256KB).

### Finding 4: branch_purity Always Zero (Non-blocking)

The `branch` field is `None` for all 1000 decisions in the baseline metadata. The evaluation code computes `branch_purity` but it is always 0 for every method at every resolution. This metric is uninformative for the current corpus.

**Impact:** Wasted computation. The code and reports correctly do not emphasize this metric. Consider removing or annotating it.

### Finding 5: Unified Evaluation Missing Full-Text Baseline (Non-blocking)

The unified evaluation includes debiased representations (PCA2, PCA3, center-projected) and TF-IDF representations (erwaegungen, S+E) but does NOT include a full-text TF-IDF baseline. This prevents direct cross-method comparison between the sentence-embedding-based methods and the TF-IDF methods on the same857-decision subset.

**Impact:** Minor methodological gap. The individual experiment provides full-text TF-IDF results on its own decision subset, but the lack of a common-subset comparison weakens the cross-method claims.

### Finding 6: Citation Graph Coverage Not Independently Verifiable (Non-blocking)

The report claims "50 of 1000 baseline decisions appear in the citation graph (5%)" but this count cannot be independently verified from the saved results. The citation graph data is loaded from `/tmp/lex_accepted/corpus/corpus/normalization/canonical/citation_graph.json` at runtime and not persisted.

**Impact:** Low. The 5% coverage claim is consistent with the graph experiment's marginal results. If the citation graph is expanded in a future cycle, the coverage count should be persisted.
