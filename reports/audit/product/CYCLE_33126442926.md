## Changes in This Cycle

### 1. Schema Validator (`app/schema_validator.py` — NEW FILE)

**Purpose:** Validates user-imported corpus records against the LexMachina canonical decision schema (based on corpus lane's `decision_schema.json` v1).

**Key Components:**
- `ValidationResult` dataclass: `valid`, `errors`, `warnings`, `normalized_record`
- `SchemaValidator` class with:
  - Required fields: `decision_id`, `court`, `docket_number`, `decision_date`, `language`, `full_text`, `provenance`
  - Enum validation for court, language, branch, outcome, decision_type, provenance source
  - Date format validation (YYYY-MM-DD)
  - Decision ID pattern validation (`^[a-z]+_[A-Za-z0-9_./-]+$`)
  - `strict` mode toggle for enforcement vs. warnings
  - Auto-normalization: ensures `provenance.source="user_upload"`, generates SHA-256 `content_hash`, adds `acquired_at` and `source_version`
- `validate_batch()` for bulk validation with summary counts
- `create_user_import_record()` convenience function for generating valid records

**Integration:** Used by `CorpusLoader.import_records()` — replaces ad-hoc validation with structured schema validation.

### 2. Corpus Loader Updates (`app/corpus_loader.py`)

**Changes:**
- Added `SchemaValidator` instance initialized in `__init__`
- `import_records(records, strict_validation=False)` — new `strict_validation` parameter
