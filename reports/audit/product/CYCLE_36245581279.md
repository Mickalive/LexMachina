### Structural Issues

1. **factory_direction.json version mismatch**: Producer workspace state claims `factory_direction_version: 28` and `direction_version: 28`, but the actual `factory_direction.json` file in both control plane and producer workspace shows `version: 27`. The FACTORY_V28_AUDIT_READY_VERIFICATION.md documents the correction (3/26 vs 11/26 years) but the authoritative file is not updated.

2. **next_recommendation / cycle_status mismatch**: State shows `"next_recommendation": "CONTINUE..."` and `"cycle_status": "RUN"` with `"continue_recommended": true`, but the operational reality documents blockers: "BLOCKED on legal-distance dense embeddings (3/26 years complete)" and "full 174k metadata requires HuggingFace parquet". This mirrors the orchestration pathology previously fixed in CYCLE_34054959674 where RUN status caused infinite zero-delta dispatches.

3. **Scale labeling inconsistency**: Artifacts metadata.json claims `"scale": "174k"` but `n_decisions: 21228`. The report correctly notes this is a local subset, but the metadata could be clearer (e.g., `scale: "174k_subset_21k"`).

4. **Corpus branch distribution**: The state shows `"null": 6988` for branches in the 7k corpus (all decisions have null branch). This is a data quality issue in the bge_20* corpus, not a product defect.

5. **Hardcoded paths in build scripts**: Build scripts use `/tmp/lex_accepted/...` paths. The `/tmp/lex_accepted` mount does not exist (artifact publication gap noted in factory direction v27 director_note).

6. **Design patterns for 174k reps missing**: The 174k representations show `design_pattern: UNKNOWN` and `purpose: general` because they're not in the `DESIGN_PATTERNS` and `REPRESENTATION_PURPOSES` dictionaries in `map_loader.py`. Minor, easily fixable.

7. **Proximity explanation for 174k decisions fails**: Decisions from the corpus are not in the 174k map (different decision sets), so proximity fails. Expected behavior — the 174k map has its own decision IDs.
