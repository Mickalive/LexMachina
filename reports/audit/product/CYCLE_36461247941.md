### 3. Label Size Mismatch Analysis

**Root Cause**: Historical clustering runs generated label files against the 175,440-entry `metadata_174k_full_175k.json` (with placeholders) instead of the 173,963-entry embeddings/decision_ids.

**Current Impact**: 
- Extra label entries (beyond 173,963) are **silently ignored** by `MapLoader._load_fractal_map_clustering()` — `index_to_id.get(idx)` returns `None` for idx ≥ 173,963
- Cluster metadata (`cluster_metadata.json`) has **correct total sizes (173,963)** for all resolutions
- **All representations load and function correctly** — verified by test passes

**Risk**: Latent data quality issue. If label files ever have **fewer** entries than metadata, decisions would silently lack cluster assignments. Inconsistency across representations suggests non-deterministic pipeline.

**Repairability**: Repair script `repair_cited_outcome_hybrid_labels.py` exists but has **hardcoded path bug** (points to accepted base path `/home/runner/work/...` instead of producer workspace). Fixable with igraph/leidenalg install and path correction.
