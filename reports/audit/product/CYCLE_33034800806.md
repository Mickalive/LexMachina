### 4.2 Cross-Language Neighbors: Honest Negative (Informational)
The cross-language neighbor discovery returns 0 cross-language neighbors for all tested decisions. This is because the baseline map geometry is dominated by language (0.982 dominance), placing all same-language decisions in spatial proximity.

**Impact:** The feature works correctly but cannot overcome the underlying representation limitation. The state correctly documents: "Cross-language neighbors limited by language-dominant clustering."

### 4.3 TF-IDF Proximity Uses Truncated Text (Known Limitation)
The TF-IDF model uses text truncated to 2000 characters per document. This limits the model's ability to capture deep legal similarity, especially for long Swiss Federal Supreme Court decisions.

**Impact:** Text similarity scores are lower than they would be with full text. The state correctly documents: "TF-IDF model uses truncated text (2000 chars max per document)."

**Classification:** Known limitation, honestly documented.

### 4.4 Cross-Language Neighbors Method Rebuilds Summaries Per Call (Minor Performance)
`get_cross_language_neighbors` and `get_text_similarity` in `navigation.py` rebuild the full `corpus_summaries` dict on every call (O(n) for 1000+ decisions). This is correct but not cached.

**Impact:** API response time for these endpoints is higher than necessary. At 1000 decisions, the overhead is modest (~10ms estimated) but would scale poorly.

**Classification:** Minor performance issue. Not a correctness defect. Could be addressed in a future optimization cycle.

### 4.5 TF-IDF Shared Terms Lookup Is O(n) (Minor Performance)
In `tfidf_proximity.py` line 171, the token-for-index reverse lookup iterates the entire vocab dict per shared term. For a vocab of 22,852 and ~30 shared terms, this is ~685K iterations.

**Impact:** Sub-millisecond in practice. Not a functional issue.

**Classification:** Minor code quality issue. Not blocking.
