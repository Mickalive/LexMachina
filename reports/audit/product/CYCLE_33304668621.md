## 2. Independent Recomputation & Verification

### 2.1 FIX-007: Caching Pattern

**Old pattern** (fragile):
- `func()` was a lambda calling `self._json_response(data)`
- `_handle_cached` monkey-patched `self._json_response` to intercept the call and capture `data`
- `try/finally` block restored original `self._json_response`
- Race condition: if `_json_response` was called before monkey-patching or after restoration, data was lost

**New pattern** (robust):
- `func()` is a lambda that **returns** the data dict (e.g., `lambda: get_nav_api().get_proximity_explanation(id_a, id_b)`)
- `_handle_cached` calls `func()`, caches the result, then calls `self._json_response(data)` to send

**Verification:** All 6 cached endpoints updated consistently (proximity, cluster_coherence, zoom_coherence, cluster_language, cross_language, text_similarity). Each lambda changed from `lambda: self._json_response(...)` to `lambda: ...` (returning data). The `_handle_cached` method caches before sending, ensuring correctness.

**Verdict:** Legitimate bug fix. Genuine improvement in robustness. No regression risk.

## 5. Code Quality Notes

### 5.1 Pre-existing issues (NOT introduced by this cycle)

1. **Docstring placement:** Several methods in navigation.py have docstrings after `if representation is None` statements, making them dead string literals (e.g., `_compute_import_positions` at line 231, `get_map_data` at line 373). Not introduced by this cycle.

2. **`send_header` before `send_response`:** In `_handle_cached`, `self.send_header("X-Cache", "MISS")` is called before `self._json_response()` which calls `send_response()`. The header may be lost. Same in both old and new code; no regression.

### 5.2 Design limitation (known)

`_compute_import_positions` uses k-NN from the base 768-dim embedding space for ALL representations, regardless of each representation's actual signal space. For representations based on different signals (e.g., cited_decisions_tfidf), the k-NN position may not be meaningful. This is a known design trade-off, not a bug.
