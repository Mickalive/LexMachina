## 6. Findings

### R1 — MATERIAL: the cycle's new durability producer is forgeable
`product/rebuild_served_packet.py --leg-report` emits a schema-identical
"green" record from **any** JSON. Auditor demonstration:

```
$ cat fake_leg.json      # 12 lines: slug + the 5 frozen ids + mode/evidence_tier strings
$ python product/rebuild_served_packet.py --leg-report fake_leg.json --out fake_out.json
business-judgment-rule: frozen cited 5/5 (passes=True); leg_gates_passed=True; mode=live
rc 0
```

The emitted record claims `retrieval_mode: live`, `evidence_tier:
CI_TEAM_JOB_LIVE`, `recall_gate…{passes: true, n: 5, of: 5}` — indistinguishable
in shape from the genuine one committed this cycle (which says 4/5). The function
validates nothing structural: no `gates`/`decision_count`/`validation_errors`
fingerprint, no cross-check between top-level `cited_decision_ids` and
`answer.cited_decision_ids`, no binding to an executed run. And the new suite
*pins* the forgeable behaviour as intended:
`test_leg_recall_record_from_a_synthetic_full_citation_set` builds a leg with
`run_id: "SYNTHETIC"` and asserts a green 5/5. The only negative control in the
file (`…_cli_check_fails_on_a_tampered_reference`) protects the `--check`
*compare*, not the *authentication* of the new mode's input.

This matters because the same file's bundle path is deliberately
provenance-bound (deterministic rebuild + reference compare + canonicalisation),
the previous repair round's whole REQUIRED-1 fix was about raising that standard,
and this cycle adds a sibling mode that drops it while emitting the same schema
family and the same `passes` semantics. The claim this artifact carries ("green
on a third live execution, recomputable offline") is **true today** — I verified
the underlying leg genuinely — but the tool would equally certify a fabricated
one tomorrow.

## 7. Why BLOCKED and not REVISE

The product claims in this cycle are honest and the shortest user-visible
capability is intact, and R1–R4 are each mechanically repairable in one cycle.
This gate is **not** a judgement that the code is unfixable. It is BLOCKED
because both of the auditor's escalation conditions are met:

1. **The repair pathology is recurring and demonstrably not converging.** Three
   consecutive audits of this lane found the *same class* of defect — claim-bearing
   prose that does not match the artifacts: `CYCLE_38964140248` (F4a "x2 runs"
   against one artifact, F4b "failure set byte-identical" that was not, F4c "54
   cache files" against 70, F4d a non-git-object digest presented as a frozen
   benchmark recompute); `CYCLE_38969438223` (A2, A4, A5 — same class, demoted to
   advisories); `CYCLE_38993348615` (REQUIRED-2, again report/artifact
   provenance). This cycle adds four more instances of that class (R2, R3, R4a,
   R4b) **and** ships a new mechanism (R1) that lowers the evidentiary standard
   the previous round had just raised. Repair round 2 re-opened the same question
   instead of closing it; a third round is the definition of infinite REVISE.
2. **A direction-level decision is required that this lane cannot make and the
   owner must not be asked to make about the product.** The served packet is gated
   by an accepted independent DO-NOT-SERVE order and both frozen bars are red
   (counter-label support 5/65 vs absolute 1.0; geometry 0/3 bundles passing all
   11). The producer's own state says the only paths to those bars are two
   capabilities ceded to other lanes ("integrate them on acceptance, do not
   re-measure them here") and that the owner must not be asked to review. Against
   that, this cycle shipped **zero user-visible delta** (no change to
   `product/static/`, `product/query/`, `server.py`, `query_app.py`, `pipeline.py`)
   and five consecutive cycles have gone unaccepted, two of the last four audit
   jobs having died on the 2700 s work quantum (`117270363753`, `117290678869`).
   Whether lane=product should keep spending cycles on audit-readiness and packet
   machinery, or pivot to user-visible capability, is a factory-direction choice
   (AGENTS.md #13), not a lane-local call.

The one-shot is a genuinely good idea and it does compress recomputation (this
audit re-derived the whole headline set in ~35 min of tool time and would have
been the rc-78 pattern without it). It does not touch the class that keeps
failing, and as shipped it certifies less than it says (R3) from an unauthenticated
input path (R1).
