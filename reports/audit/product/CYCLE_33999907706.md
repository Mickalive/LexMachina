### FEAT-078: TF-IDF Truncation Fix ✅ VERIFIED

**Claim:** Fix TF-IDF model building truncation — use untruncated text for model building, keep 8000-char limit for API responses.

**Implementation Verified:**
- `Decision.to_full_raw()` — returns untruncated full decision text (new method)
- `Decision.to_full()` — truncates at 8000 chars + "... [truncated]" marker (limit raised from 2000)
- `CorpusLoader.get_all_decisions_raw()` — returns list of untruncated decisions for NLP consumers
- `NavigationAPI.initialize()` — calls `corpus.get_all_decisions_raw()` for TF-IDF model building

**Test Evidence:** 3/3 tests PASS
- `test_decision_to_full_truncation` — verifies 8000-char truncation
- `test_decision_to_full_raw_no_truncation` — verifies untruncated preservation
- `test_corpus_loader_raw_accessor` — verifies raw accessor returns untruncated text for decisions > 2000 chars

**Attack Surface:** No data leakage. API responses still truncated; only internal model building gets full text. Correct separation of concerns.

### FEAT-080: Cross-Language Neighbors by TF-IDF Text Similarity ✅ VERIFIED

**Claim:** TF-IDF text similarity finds cross-language neighbors, overcoming language-dominated 2D map geometry.

**Implementation Verified:**
- `LanguageAnalyzer.find_cross_language_neighbors_by_text()` — computes cosine similarity on TF-IDF vectors, filters to cross-language candidates only, returns ranked by text_similarity
- `TFIDFProximity.build_from_corpus()` — builds from untruncated corpus text (uses `erwaegungen` > `sachverhalt` > `full_text` priority)
- `NavigationAPI.get_cross_language_neighbors()` — returns BOTH spatial (language-dominated) AND text-similarity (language-invariant) neighbor sets with method note

**Test Evidence:** 2/2 tests PASS
- `test_find_cross_language_neighbors_by_text` — verifies cross-language discovery, same-language exclusion, similarity scoring
- `test_cross_language_neighbors_sorted_by_similarity` — verifies ranking by text similarity

**Attack Surface:** 
- TF-IDF vocabulary built from 1000/1200 decisions — limited coverage for rare legal terms
- No holdout validation of cross-language retrieval quality (infrastructure only, not yet benchmarked)
- Simple tokenization (regex + stopword list) — may miss compound legal terms in German
