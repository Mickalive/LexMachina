### Defect 2 — 21 tracked query-cache envelopes rewritten in place, committed with no accounting (integrity/disclosure)

Evidence:

- `git diff origin/lab/product..HEAD --name-status`: 21 `M` files under
  `results/product/query_cache/`, all in this run's commit 9634c5b (the prior
  commit e5f145f only *added* 31 envelopes — append-tolerant).
- Rewrites carry fresh `fetched_at` 2026-10-24 01:00:24–01:02:29 UTC (live
  `/api/decisions?...` and `/api/decisions/<id>?full_text=true` URLs) — i.e.
  a `live`/`refresh` retrieval against the tracked cache root during this run.
- 20/21 are covered by the frozen snapshot in force
  (`CYCLE_39799042649_cache_manifest.json`) and SHA-mismatch it (the 21st,
  `81/8143…`, postdates that snapshot and was touched only by 5e3013c and this
  commit).
- `python3 product/cache_rewrite_attribution.py --check`:
  base = *"13 mismatched, 0 missing"* (pre-existing, disclosed by prior audits),
  head = *"33 mismatched, 0 missing"*. This cycle added all 20.
- `results/product/cache_attribution/` contains **no** artifact for this run;
  `state/product.json` unchanged (no cache note); **no producer cycle report
  exists** for 40039651192, 40044664367 or 40046177742.
- All three committed live-slice records fingerprint ephemeral `/tmp` roots with
  `n_files_modified=0` — by their own bytes they own none of the tracked
  writes. The bytes remain recoverable from git history (no irretrievable loss;
  rewritten content is genuine fresh upstream data, not fabricated), so this is
  an accounting/disclosure defect, revivable with a mechanical repair.

Mitigating: `test_cache_non_orphan.py` (15 passed) is green by the D3 contract —
committed rewrites are "attributed" to the rewriting commit itself — which is
exactly why the currency check (`--check`) and a disclosed owning run are the
only real guards, and both are missing here.

**Repairs (either branch):** (a) identify/re-run a recorded tracked-cache run
(e.g. `live_slice.py --tracked-cache`), publish its record, then
`cache_rewrite_attribution.py --run-id <run> --write` and `--write-snapshot` so
`--check` exits 0; **or** (b) restore the 20 snapshot-covered envelopes to their
pre-cycle committed bytes and re-verify the offline slice. Whichever branch, the
cycle must publish the cache accounting so `--check` returns to the disclosed
baseline and the committed records no longer imply the tracked cache was
untouched this cycle.
