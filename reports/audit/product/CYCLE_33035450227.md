## 4. Specific Findings

### 4.1 sachverhalt == sachverhalt_erwaegungen_dispositiv (Informational)
The `sachverhalt` and `sachverhalt_erwaegungen_dispositiv` section modes have identical projections (max diff = 0.0). This originates from the upstream `section_experiment_clean` data where these two modes produced identical results. The product correctly loads and serves both modes as separate views.

**Impact:** Users see two distinct mode labels but get identical map positions. The mode descriptions differ ("Facts" vs "Facts + Reasoning + Holding") but the visualization is the same.

**Classification:** Data limitation from upstream lane. Not a product defect. The product could benefit from a deduplication check or mode-comparison indicator, but this is an enhancement, not a fix.

### 4.2 get_position_details Returns has_section_data=True for All Positions (Minor)
In scaled mode, `get_position_details()` returns `has_section_data: True` for all 1000 positions, including the 937 baseline fallback positions. The provenance data in `metadata.json` correctly distinguishes section_projection vs baseline sources, but this information is not surfaced through the `get_position_details` API.

**Impact:** Users cannot distinguish section-specific positions from baseline fallback positions via the position details API. The coverage string ("63 of 1000 decisions have section-specific projections, 937 use baseline fallback") is shown in the mode metadata, but individual position provenance is not exposed.

**Classification:** Minor API design gap. Not a blocking defect. The underlying provenance data exists and could be surfaced in a future cycle.

### 4.3 State Lists 34 Features, Report Claims 33 (Minor Documentation Discrepancy)
The state `navigation_features` array has 34 entries, but the report states "33 navigation features." The state is authoritative.

**Impact:** Documentation only.

**Classification:** Minor. No code defect.

### 4.4 Temporal Filtering Limited by Corpus Composition (Known Limitation)
All 1000 map decisions have year=2024. The corpus has 50 decisions each from 2020-2023 and 1002 from 2024, but the map positions are exclusively 2024 decisions. Temporal filtering works correctly on this data but provides no year diversity.

**Impact:** The temporal slider shows a single year (2024) for all map positions. The feature is functional but has limited utility with this corpus composition.

**Classification:** Known limitation. The state documents: "Temporal filtering requires year metadata in corpus (not all decisions have it)." The corpus composition issue is upstream.
