### 1. Navigation API Fix — `product/app/navigation.py` (Lines 1100-1122)

**Diff:**
```python
# BEFORE (audit-base):
map_positions = self.map_loader.get_positions("concat_center_tfidf")

# AFTER (team branch):
default_rep = self._get_default_representation()
map_positions = self.map_loader.get_positions(default_rep)
# ... fallback chain to 174k reps, then baseline
```

**Analysis:**
- The product has been operating at **174k scale** (173,963 decisions) since factory direction v27+
- Production default representation is `cited_outcome_hybrid_0.5_174k` (documented in `_get_default_representation()`, state/product.json, and factory direction v29)
- The old code computed coverage against `concat_center_tfidf` (1k baseline, ~1,000 positions)
- This produced **misleading coverage statistics**: corpus_map_coverage was reported as ~100% against the 1k map but actually ~4.6% against the 174k production map (7,990 corpus decisions / 173,963 map positions)
- The fix correctly uses `_get_default_representation()` with a fallback chain to other 174k representations, then baseline

**Evidence from state/product.json:**
- `map_positions_total: 173963`
- `map_positions_in_corpus: 7990`
- `corpus_map_coverage: "4.6%"`
- `174k_tfidf_modes_operational.cited_outcome_hybrid_0.5_174k: "PRODUCTION DEFAULT per v15b-audit"`

**Verdict: VALID BUG FIX** — Correctly aligns product metrics with the actual production map scale.
