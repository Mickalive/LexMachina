## Changes Under Audit

### 1. `product/app/navigation.py` — WebGL Pipeline Optimization (`get_webgl_data`)

**Location**: Lines 2429–2697 (producer workspace), replacing lines 2429–2799+ (accepted base)

**Change Summary**: Complete rewrite of the optimized code path for non-section-mode representations.

**Before (Accepted Base)**:
```python
# Called get_map_data() which enriches ALL positions with corpus data
map_data = self.get_map_data(representation=representation, zoom_level=zoom_level)
positions = map_data.get('positions', [])
clusters = map_data.get('clusters', [])
# Then applied LOD/culling on already-enriched data
```

**After (Producer Workspace)**:
```python
# OPTIMIZED PATH: Use raw zoom level data, enrich only after culling
zl = self.map_loader.get_zoom_level(representation, zoom_level)
# Build numpy arrays directly from raw positions (no corpus.get_summary calls)
# Apply LOD decimation BEFORE enrichment
# Apply viewport culling BEFORE enrichment
# NOW enrich only the visible/remaining points (after LOD + culling)
```

**Optimization Impact**:
| Scenario | Old Path | New Path | Reduction |
|----------|----------|----------|-----------|
| LOD 0 (cluster centroids) | Enrich 173,963 | Enrich ~31 | **5,612x** |
| LOD 1 (super-clusters) | Enrich 173,963 | Enrich ~100s | ~1,000x+ |
| Viewport culling (full detail) | Enrich 173,963 | Enrich viewport subset | Proportional to viewport |

**Correctness Assessment**: ✅ **Correct and Significant**
- Raw zoom level data (`zl.positions`, `zl.cluster_assignments`, `zl.clusters`) is the authoritative source
- Corpus enrichment (`get_summary`, `_get_map_decision_meta`) is expensive I/O — correctly deferred
- Transform uses full data extents (`xs.min()/max()`) for consistent coordinate space — **preserved**
- Cluster color map built from `clusters_processed` (original clusters) — **correct**; LOD points assigned to nearest centroid
- Imported flags handled correctly — LOD points get `False` (synthetic)
- Cache key logic preserved: only caches non-viewport requests (`bbox is None`)
- Section mode path (`map_mode` branch) unchanged — still uses `get_map_data()` (correct, smaller datasets)

**Edge Cases Verified**:
- Empty zoom level → returns error (line 2484–2485)
- No positions after culling → returns empty arrays (handled by loop at line 2578)
- LOD points get placeholder IDs (`lod_cluster_{cid}_{idx}`) and `language: "unknown"` — appropriate
- Frustum planes computed for GPU-side culling when `bbox` provided — **preserved**

## Attack Surface Analysis

### 1. Performance Optimization Correctness
- ✅ **No data loss**: Full data extents preserved in `transform` for coordinate mapping
- ✅ **Cluster integrity**: Original cluster metadata (`clusters_processed`) retained; LOD points mapped to nearest centroid
- ✅ **Import handling**: Imported decisions correctly flagged; LOD points marked non-imported
- ✅ **Cache behavior**: Non-viewport requests cached; viewport requests dynamic — **unchanged**

### 2. Backward Compatibility
- ✅ **Section modes**: Unchanged code path via `get_map_data()` — no regression risk
- ✅ **API contract**: Return structure identical (`points`, `clusters`, `transform`, `frustum_planes`, `lod_decimation`, `viewport_culling`)
- ✅ **Error handling**: Same error format for missing zoom levels

### 3. Memory/CPU Efficiency
- ✅ **Numpy pre-allocation**: `np.empty()` avoids list append overhead
- ✅ **Vectorized operations**: Centroid distance computation uses broadcasting
- ✅ **Single enrichment pass**: Only visible points enriched

### 4. Potential Risks (Mitigated)
| Risk | Mitigation |
|------|------------|
| LOD cluster assignment incorrect | Nearest-centroid assignment uses same `clusters_processed` as color map |
| Transform mismatch | Uses `xs`/`ys` from full data (before LOD/culling) |
| Missing imported flags for LOD | Correctly set to `False` (synthetic points) |
| Cache pollution | Viewport requests (`bbox` provided) explicitly NOT cached |

### 5. Requirements Alignment
- Factory Direction v29: "WebGL/LOD/culling pipeline validated at 174k scale (PCA projection for cited_outcome_hybrid_0.5_174k fixed)" — **optimization directly supports this**
