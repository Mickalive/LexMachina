## 2. R1 (material) — false causal claim for the live counter-anchor abstention

**The claim.** `reports/product/CYCLE_20261017_COUNTER_ANCHOR_INTEGRATION.md` lines 101–104:

> "The counter-anchor integration is active: `bge_BGE_110_II_391` → `abstained_unevidenced` (its cited
> evidence failed the frozen rubric)."

and `state/product.json` → `counter_anchor_integration.live_evidence_this_run.abstained_example`:

> "bge_BGE_110_II_391 -> abstained_unevidenced (cited evidence failed frozen rubric)"

**Recomputation.** The reality runner passes the frozen French BJR question
(`product/reality_check.py::LEGS["business-judgment-rule"]`, lines 77–81) as `question` into
`run_query_initial` / `enrich_query_bundle` (lines 490, 501, 503). The adapter is called as
`apply_counter_anchor_decisions(audited)` with **no `qid`** (`product/query/pipeline.py`), so it resolves
the qid from the bundle query via `resolve_qid` (substring match against the five authored
`question_anchors`). Auditor ran it:

```
resolve_qid("<BJR question>", rules) -> None
```

The five authored anchors are `de-kapitalverletzung`, `fr-bail-entretien`, `it-responsabilita-medica`,
`kuendigung-mietrecht`, `responsabilite-penale-entreprise-102cp`. The BJR question matches none. With
`anchor_profile is None` the adapter takes the fail-closed branch (`counter_anchor.py` lines 210–221):
every proposed label becomes `counter_status="abstained_unevidenced"`,
`counter_reason_code="no_anchor_profile"`, `counter_uncertainty=1.0`, `counter_evidence_verified=False`.
`decide_label` / the frozen rubric is **never invoked**. Independent replay on the BJR query confirms
`abstention_reasons == {"no_anchor_profile": 1}`, `qid=null`.

So the true cause of the `bge_BGE_110_II_391` abstention is "no authored anchor profile for this query
(fail-closed)", not "cited evidence failed the frozen rubric". The state file itself contains the correct
general rule (`behavior.unknown_qid` = "fail-closed: every proposed label abstained with reason
`no_anchor_profile`"), so the two statements are mutually inconsistent within one claim-bearing artifact.

**Why this matters.** This is the cycle's *headline live evidence* for the new component, and it is the
only place the report presents the integration as having actively evaluated a real live row. It did not.
Independently, the live report's `cited_decisions` projection writes `counter_status` but not
`counter_reason_code` (`reality_check.py`), so a reader of the artifact cannot see the reason and the
false parenthetical is the only explanation offered. The claim is exactly the class of unsupported
positive claim the audit exists to catch.

**Fix (concrete, same-cycle).** Either
(a) correct both texts to state the fail-closed reason, e.g. *"bge_BGE_110_II_391 → abstained_unevidenced
(fail-closed: no authored anchor profile for the business-judgment-rule query; the frozen rubric was not
applied)"*, or
(b) make the claim verifiable by recording `counter_reason_code` in the reality-check
`cited_decisions` projection, then restate the cause accurately.

This is **not** the recurring pathology of prior cycles (fabricated frozen-gate greens, non-reproducible
statistics), so it is a REVISE, not a BLOCKED.
