## Adversarial Review

### Leakage Check

**CONCERN:** The 21,228 decisions come from `metadata_174k_full.json` which has `branch='null'` (string) and `legal_area=None` for all entries. The build script attempts enrichment from corpus files (`bge_20*.jsonl`) but uses the wrong glob pattern (`bger_20*.jsonl`). **No enrichment occurs**, so all downstream purity metrics are 0.0. This is not data leakage per se, but a **silent data quality failure** that invalidates zoom_coherence.

### Benchmark Gaming

**NOT APPLICABLE:** This cycle does not run benchmarks. The benchmark scores cited (JP=0.7990, LangDom=0.4911) are from factory direction v9/v15b-audit at 1k/7k scale. The 174k representations claim the same scores without re-validation at 174k scale.

### Prettiness-as-Quality

**NOT APPLICABLE:** No visualization changes.

### Weak Baselines

**PARTIAL CONCERN:** The 174k representations use hierarchical Leiden (coarse=0.5, fine=3.0, k=15) with nesting=1.0 by construction. However, the fractal-map lane audit CYCLE_36027099305 (PASS, ACCEPTED) established **NESTING_METRIC_DEFECT_v1**: compressed 5-level ladder does NOT preserve strict nesting for most modes (honest mean change -0.00364, range [-0.0556, +0.1150], 21/22 modes nonzero). The 7-level ladder here has the same defect. The claim "nesting score: 1.0 (by construction)" is technically true but misleading per the accepted claim ceiling — it only holds for the compressed construction, not for true hierarchical preservation.

### Structural Issues

1. **Critical: Corpus glob bug in new build scripts** — Both `build_174k_tfidf_clustering.py` (line 116) and `build_174k_tfidf_clustering_full.py` (line 96) use `CORPUS_DIR.glob("bger_20*.jsonl")` but corpus files are `bge_20*.jsonl`. This was fixed in prior cycle for `build_174k_production.py` and `build_all_representations.py` but **regressed in new scripts**. Result: metadata enrichment fails → all decisions have `branch='null'` → zoom_coherence 0% improvement rate.

2. **Scale mislabeling** — Representation names contain "174k" but artifacts cover only 21,228 decisions (12% of 174k). The cycle report honestly notes this as "local metadata subset" but the representation names and display names imply full 174k scale.

3. **State files stale** — `state/product.json` not updated with new representations, scale, or counts. `state/factory_direction.json` at v26 vs claimed v27. This mirrors the orchestration pathology previously fixed in CYCLE_34054959674.

4. **No test coverage for new 174k representations** — Critical gap. The new representations are loaded and served but have no dedicated tests verifying their zoom ladder, cluster counts, or API behavior.

5. **Zoom coherence invalidated** — All three 174k representations show 0.0 coarse/fine purity, 0 improvements, 0% improvement rate because branch metadata is missing. This is a direct consequence of bug #1.

6. **factory_direction.json version drift** — Producer workspace has v26; accepted base has v27. The cycle report claims v27 but the control plane hasn't been updated.
