### Structural Issues

1. **Design patterns for 174k reps missing**: The 174k representations show `design_pattern: UNKNOWN` and `purpose: general` because they're not in the `DESIGN_PATTERNS` and `REPRESENTATION_PURPOSES` dictionaries in `map_loader.py`. Minor, easily fixable.

2. **Scale labeling inconsistency**: Artifacts metadata.json claims `"scale": "174k"` but `n_decisions: 21228`. The report correctly notes this is a local subset, but the metadata could be clearer (e.g., `scale: "174k_subset_21k"`).

3. **Corpus branch distribution**: The state shows `"null": 6988` for branches in the 7k corpus (all decisions have null branch). This is a data quality issue in the bge_20* corpus, not a product defect.

4. **Hardcoded paths in build scripts**: Build scripts use `/tmp/lex_accepted/...` paths. The `/tmp/lex_accepted` mount does not exist (artifact publication gap noted in factory direction v27 director_note).

5. **State not yet updated**: The `state/product.json` in both control plane and producer workspace still shows `corpus_decisions_loaded: None` and `map_representations: 0`. State update should occur after this cycle passes.

6. **Proximity explanation for 174k decisions fails**: Decisions from the corpus are not in the 174k map (different decision sets), so proximity fails. Expected behavior — the 174k map has its own decision IDs.
