## 3. Blocking defects

### F1 — the second half of the delta is dead code resting on an impossible premise (MODERATE)

`ocl_adapter/bundle.py:220` flattens the adapter's variant dicts before the product ever
sees them:

```python
"query_variants": [v.get("text", "") for v in bundle.get("query_variants", [])],
```

and `product/query/bundle.py:20` types the field as `list[str]`. Every product path
(`pipeline.py:421`, `progressive.py:332`, `adversarial_retrieval.py:788`) passes strings.
**The dict branch of `_variant_texts()` can never execute in production.**

Measured, not inferred:

* Offline replay records `query_variants_used: 7` identically on base and head, and
  `query_variant_kinds: ["text"]` — the new provenance field can only ever record the
  constant `"text"`, i.e. it carries no information.
* Reverting the call site to the old `[str(v) for v in …]` while keeping the helper
  changes the entire BJR bundle by **exactly one leaf**: the new
  `provenance.product_rerank.query_variant_kinds[0]` key. Every similarity, rank,
  recall decision, cluster and served row is identical.

So the docstring's *"Production bundles carry the accepted adapter's variant dicts"* and
*"observed 2026-10-16 on the business-judgment-rule leg, where the German
`legal_concept` variants were present but buried ~10x under repr noise"* describe a
phenomenon that cannot occur. The report's softer wording — *"measured and found
non-binding"* — is still wrong in kind: the cause was never measurable, because the
condition never arises.

Compounding it, the accompanying test cannot fail for the reason it claims:

* `test_reranker_dict_variants_do_not_dilute_concept_vocabulary` imports
  `_variant_texts` and tests the helper in isolation. With the integration reverted to
  `str()` and the helper left in place, the file is **19/19 green**. Its docstring
  promises that "the fixed extractor keeps the query document identical to the
  plain-string form used by fixtures" — nothing asserts that, and nothing can.
