## Capability under audit

Does real/cached OpenCaseLaw input produce a source-linked result bundle and clickable map,
and are zero-cost/source-validity claims true?

This is the shortest user-visible capability in the evaluation lane: the query-map MVP. The
benchmark (`evaluation/query_map/run_cached_bundle_benchmark.py`) exercises three legs on
real cached OpenCaseLaw envelopes:

1. **leg 1 — producer_baseline**: build a `query_result_bundle` from the cached OpenCaseLaw
   response cache and run the accepted harness (`evaluation.query_map.harness.evaluate_query_map_bundle`).
   Every harness check must be true. Exit 1 means the DATA PLANE cannot honour the bundle contract.
2. **leg 2 — falsification_blanked_counter_evidence**: strip `counter_evidence` from every
   counter-labelled decision. `counter_classifications_supported` must go FALSE. Proves the
   counter-evidence contract is live on real rows, not vacuous.
3. **leg 3 — falsification_broken_source_url**: repoint one decision's `canonical_url` off
   `mcp.opencaselaw.ch`. `source_urls_valid` must go FALSE. Proves source validity is live on
   real rows, not vacuous.

**Exit codes:** 0 = BENCHMARK_VALID_NO_FALSIFICATION; 1 = BUNDLE_CONTRACT_VIOLATED; 2 =
ENVIRONMENT_OR_VACUOUS.

## Claim ceiling

This benchmark proves only that **REAL cached OpenCaseLaw rows carry the fields the
query_result_bundle contract needs** (decision_id, canonical_url on mcp.opencaselaw.ch,
language, citation strings, statutes, a frozen-marker-rule text surface) and that the
ACCEPTED harness rejects a regressed bundle. It does NOT prove that Product builds such a
bundle, that the map is useful to a jurist, that counter labels are calibrated
(counter_uncertainty is a fixed fixture constant), that the coordinates are a good layout
(they are a deterministic fixture-grade layout, not a geometry claim), or anything about the
absolute LABEL_SOUND / GEOMETRY_SOUND bars. Recall figures are measured, not thresholded.
