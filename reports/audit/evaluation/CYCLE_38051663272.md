## 4. Defects Requiring Repair

### D-1 (same-cycle repairable) — advertised hard-fail guard is broken

- **File:** `evaluation/verify_frozen_baseline.py`
- **Evidence:** line 165 reads `if os.environ.get("LEX_ENFORCE_METADATA_PIN", "0") == "1":`, but `os` is not
  imported anywhere in the module (imports are `json, numpy, logging, sys, time, hashlib, pathlib, typing,
  collections, sklearn`; `platform`/`sklearn` are imported locally in the guard block). Static AST check
  confirms `os imported: False`.
- **Effect:** the guard's documented behaviour ("Hard-fail is available via `LEX_ENFORCE_METADATA_PIN=1`",
  report §3.1) is not implemented. On a metadata-pin mismatch with the env var set, the process raises
  `NameError` rather than the intended `SystemExit(2)`; it does still exit non-zero, so the functional block
  survives, but the artifact does not match its description and would be untested on its intended path.
- **Repair:** add `import os` (or gate via the already-imported modules) so the enforce branch exits cleanly.

### D-2 (same-cycle repairable) — provenance pointer mislabelled / self-contradictory

- **File:** `results/evaluation/frozen_baseline_reproducibility/provenance.json`
- **Evidence:** `pre_verification_latest_sha256 = 6514501d…` and
  `pre_verification_pointer_metrics.jurist_preference_rate = 0.5925` refer to
  `PRE_verification_latest_rerun.json` (the **post-run** rerun), whereas the report (§2.2/§3) and
  `OPERATIONAL_RESUME_38051663272_DIAGNOSIS.json` (`pre_run_pointer_preserved`, `jp=0.659`) correctly identify
  the pre-repair pointer as `PRE_verification_latest.json` (`cff6b19e722b…`, `JP=0.659 / LD=0.425775`), which is
  byte-identical to the accepted base's `verification_latest.json`.
- **Effect:** the dedicated provenance record for this repair contradicts the repair's own report/diagnosis and
  would mislead a future reader about what the pre-repair state was.
- **Repair:** point the `pre_*` fields at the archived pre-repair artifact (`cff6b19e722b…`, JP=0.659 /
  LD=0.425775), and/or rename them to state unambiguously that the `6514501d…` rerun is post-run (e.g.
  `rerun_verification_latest_sha256`).
