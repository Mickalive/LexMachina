### 2.1 Independent verification of query_map evaluator

The query_map harness (`evaluation/query_map/harness.py`) is stdlib-only and consumes JSON bundles (does not import Product code). It checks:
- `bundle_nonempty` — bundle must contain decisions
- `duplicate_free` — no duplicate decision IDs (duplicates == 0)
- `source_urls_valid` — canonical_url must be https and hostname must be `mcp.opencaselaw.ch` (per source validity requirement)
- `answer_citations_constrained` — cited_decision_ids must be subset of final decision set (prevents invented citations)
- `counter_classifications_supported` — counter_status must have evidence and uncertainty if classified as counter (COUNTER_STATUSES = {"limiting", "contrary_or_exception", "candidate-limiting", "candidate-contrary"})
- `geometry_preserved_after_enrichment` — initial vs final geometry signature preserved (x,y,cluster_id,is_outlier stable after enrichment)
- `progressive_phases` — initial phase "map_ready" → final phase "complete"
- `no_fixture_in_live_claim` — no "fixture" keyword in remote retrieval when fixture_mode is False

All 6 tests in `test_harness.py` pass (verified independently):
- test_happy_path_and_recall ✓ (recall 1.0, geometry preserved, source_validity enforced)
- test_invented_citation_fails ✓ (answer_citations_constrained false)
- test_counter_without_evidence_or_uncertainty_fails ✓ (counter_classifications_supported false)
- test_geometry_change_fails ✓ (geometry_preserved_after_enrichment false)
- test_bad_source_and_duplicate_fail ✓ (source_urls_valid false, duplicate_free false)
