## Pillar-by-Pillar Verification

### Pillar 1: Full 12-Benchmark Formal Suite (V25 Protocol) — 174k TF-IDF Family

**Claim in Report:** "8/8 TF-IDF representations evaluated with frozen harness v3 (config hash `b51701f5a9c11692` for adversarial, `4323f833fa72366a` for v25 suite); exact reproduction verified 2026-09-28, 2026-09-29, 2026-09-30"

**Findings:**
- **Two distinct evaluation protocols exist** and the report correctly identifies both config hashes:
  - **Formal suite v3 (exact k-NN):** `evaluation_174k_formal_suite_latest.json` uses `sklearn_exact` on stratified subsample n=2000, config hash `b51701f5a9c11692`. All 8 representations PASS both adversarial gates (LangDom ≤ 0.85, JuristPref > 0.5). Production default `cited_decisions_tfidf_outcome_hybrid_0.5`: LangDom=0.4773, JuristPref=0.7345.
  - **V25 formal suite (HNSW):** `_suite_summary.json` uses HNSW (M=16, ef_construction=200, ef_search=100), config hash `4323f833fa72366a`. Shows **different adversarial results**: text-based representations FAIL (LangDom≈1.0), citation-based PASS.

- **Report accuracy:** The summary table in the report matches the **formal suite v3 (exact k-NN)** results, not the v25 HNSW results. The table shows:
  - Citation-based (5 reps): PASS adversarial ✓ (matches formal suite v3)
  - Text-based (3 reps): FAIL adversarial (LangDom≈1.0) — **this matches v25 HNSW, NOT formal suite v3 where all 8 PASS**

- **Critical discrepancy:** The report's Table 1 says text-based representations FAIL adversarial with "LangDom=1.0", but the formal suite v3 exact k-NN shows ALL 8 PASS adversarial (max LangDom=0.5015 for `outcome_tfidf`). The LangDom≈1.0 values come from the v25 HNSW evaluation.

- **Conclusion:** The report conflates two different adversarial evaluations. The "frozen harness v3" (exact k-NN) shows **no adversarial failures** for any TF-IDF representation. The v25 HNSW suite shows the language-dominance artifact. The report should explicitly distinguish these two protocols.

- **Conclusion:** Results accurately reported. The "2,040-pair pool" description is slightly ambiguous but not materially misleading.

## Issues Identified (Non-Blocking)

### 1. Conflation of Two Adversarial Protocols (Material Clarity Issue)
The report presents a single adversarial result table but mixes:
- **Formal suite v3 (exact k-NN, config b51701f5a9c11692):** All 8 PASS
- **V25 formal suite (HNSW, config 4323f833fa72366a):** Text-based FAIL (LangDom≈1.0)

The table column "Adversarial" with values like "❌ FAIL (LangDom=1.0)" for text-based reps reflects v25 HNSW, not the "frozen harness v3" claimed. This could mislead a reader into thinking the exact k-NN evaluation shows adversarial failures for text-based reps.

**Recommendation:** Explicitly label which protocol each result comes from, or present two separate tables.

### 2. Citation Heritage Pool Size Ambiguity
"Frozen 2,040-pair pool" vs. actual evaluation on 1,020-pair subsample. The monitor state clarifies this but the report should be precise: "evaluated on 1,020-pair stratified subsample drawn from frozen 2,040-pair pool."

### 3. V25 Suite vs. Formal Suite v3 Naming
The report says "Full 12-Benchmark Formal Suite (V25 Protocol)" but then cites config hash `b51701f5a9c11692` for adversarial (which is formal suite v3 exact k-NN) and `4323f833fa72366a` for v25 suite. These are **different protocol versions** with different backends. The V25 protocol uses HNSW; the formal suite v3 uses exact k-NN.

### 4. Production Default Name Inconsistency
- Report: `cited_decisions_tfidf_outcome_hybrid_0.5` (hyphens)
- V25 suite: `cited_outcome_hybrid_0.5` (underscores)
- Formal suite v3: `cited_decisions_tfidf_outcome_hybrid_0.5` (hyphens)
Minor but could cause lookup confusion.

### 5. State File Path Discrepancy
`evaluation_state.json` still has `"report_path": "reports/evaluation/evaluation_cycle_v28_report.md"` but the new report is `evaluation_cycle_v29_report.md`. The commit updated this but the state file shows v28 path — likely a timing issue (state written before commit).
