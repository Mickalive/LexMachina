## Attack Surface: Claims vs. Reality

### Claim 1: "Real/cached OpenCaseLaw input produces a source-linked result bundle"
**VERIFIED**. Every decision in every bundle carries:
- `decision_id` (non-empty)
- `canonical_url` on `https://mcp.opencaselaw.ch/entscheid/<id>` (validated by harness `source_urls_valid`)
- `language` ∈ {de, fr, it}
- `citation_strings` (de/fr/it), `statutes`, `court`, `court_level`, `decision_date`, `title`, `regeste`, `snippet`
- `retrieval_score`, `retrieval_rank`, `retrieved_by` (channel:language provenance)

The bundles are **source-linked** — every decision traces to a specific cached envelope (channel, language, cache_path_sha256, http_status).

### Claim 2: "Clickable map" (geometry-stable, deterministic layout)
**VERIFIED WITH CAVEATS**. The producer emits `x`, `y` coordinates and `cluster_id` for every decision:
- `x`: golden-ratio low-discrepancy sequence by retrieval rank (monotone in rank, rank order visually recoverable)
- `y`: SHA-256 hash of alnum-core id (deterministic, machine-stable)
- `cluster_id`: by (language, court_level) tuple

**Geometry preserved after enrichment**: `initial_geo == final_geo` for all 4 questions (harness check passes).

**Caveat — honestly disclosed in claim_ceiling**: This is a **deterministic fixture-grade layout**, not a "good" layout. No geometry quality claim is made. The coordinates are a parameterless deterministic function of (rank, id), not an optimized visualization.

### Claim 3: "Zero-cost" (offline replay, no live network calls)
**VERIFIED**. Provenance records:
- `network_calls: 0`
- `cache_hits: 6` per question (2 channels × 3 languages)
- `fixture_mode: true` with reason: "rows are replayed from the lane's raw HTTP-200 cache; this run made NO live network call and does not claim a live retrieval"

### Claim 4: "Source validity" (canonical_url on mcp.opencaselaw.ch)
**VERIFIED AND FALSIFIABLE**. Harness `source_urls_valid` checks `urlparse(canonical_url).scheme == "https" and hostname == "mcp.opencaselaw.ch"`. Leg 3 (broken source URL) **fires for all 4 questions**, proving the check is live on real rows, not vacuous.

### Claim 5: "Counter-authority layer works"
**PARTIALLY VERIFIED — NEGATIVE RESULT HONESTLY REPORTED**. The frozen `marker_rule` (norm_token AND limitation_token in title+regeste+snippet, normalized) yields:
- rent-default: 16 counter candidates
- petty-theft-dismissal: 4 counter candidates
- **corporate-criminal-liability: 0 counter candidates**
- **business-judgment-rule: 0 counter candidates**

This is explicitly published as a **NEGATIVE RESULT**: "COUNTER-AUTHORITY DISCOVERY IS EMPTY FOR 2/4 FROZEN QUESTIONS... the map's counter layer would be empty for half the query set."

The `counter_uncertainty` is a fixed fixture constant (0.5), **not calibrated, not adjudicated**. The `counter_status` is "candidate-limiting" (a candidate label, not a product-grade classification). This is all honestly disclosed in `claim_ceiling` and `counter_rule.adjudicated: false`.

### Claim 6: "No generative answer step"
**VERIFIED**. Bundle `answer` contains only `cited_decision_ids` (a set, top-3 by rank or frozen authority_ids), `text: null`, `generation: "none"`. The producer "runs no generative answer step and asserts no prose."
