## 4. Query-map MVP: shortest user-visible capability

Per the audit mandate, the shortest user-visible capability was checked first:

**Does real/cached OpenCaseLaw input produce a source-linked result bundle and clickable map?**

Yes. The `evaluation/query_map/bundle_producer.py` module takes real/cached OpenCaseLaw
HTTP envelopes from the retrieval benchmark cache and produces `{"initial": ..., "final": ...}`
query_result_bundle dicts.  The bundles contain:

- **decisions** with `canonical_url` fields (all `https://mcp.opencaselaw.ch/...`), `x/y`
  coordinates from a deterministic golden-ratio layout, `cluster_id`, `counter_status`,
  `counter_evidence`, `counter_uncertainty`
- **clusters** with `cluster_id` and `label`
- **provenance** tracking the input source ("lane-owned raw OpenCaseLaw response cache;
  offline replay"), `fixture_mode: true`, `frozen_spec_sha256`, query text, channels,
  latency=0, remote request_summary with `network_calls: 0`, `cache_hits: N`
- The accepted harness (`evaluation/query_map/harness.evaluate_query_map_bundle`) checks
  `source_urls_valid` (all canonical URLs must be `https://mcp.opencaselaw.ch`),
  `counter_classifications_supported` (evidence present AND uncertainty present for every
  counter decision), `geometry_preserved_after_enrichment`, and `progressive_phases`
  (initial phase = map_ready, final phase = complete)

**Are zero-cost/source-validity claims true?**

- **Zero cost**: `latency_seconds: 0.0`, `network_calls: 0`, the benchmark makes no live
  network calls; all data is replayed from the cached OpenCaseLaw response envelopes.
- **Source validity**: All `canonical_url` values in decisions are verified against
  `https://mcp.opencaselaw.ch` by the harness check `source_urls_valid`.  The cache
  envelopes themselves carry the original HTTP 200 status and `body_sha256` integrity
  seals.  The frozen spec is opened read-only and re-hashed by the caller — never
  guessed or re-derived.

The benchmark under audit (cycle 39691077263) does **not** itself produce map bundles;
it measures counter-authority surface on served product bundles.  But the query-map MVP
infrastructure (`bundle_producer.py` + `harness.py`) is the mechanism by which the
query-map product turns cached OpenCaseLaw input into source-linked, mappable result
bundles.  The module makes no calibration or geometry claims beyond the deterministic
fixture-grade layout documented in its own claim ceiling.
