### 3.3 Threshold Selection Attack

**Attack:** Are thresholds (0.85, 0.5, 0.3, 0.95, 0.3) set *a priori* or tuned to make center_projected pass?

**Evidence:**
- Thresholds are hardcoded in `v3_adversarial_evaluation.py` benchmark functions
- Language Dominance: `threshold: 0.85` — center_projected achieves 0.76–0.77 (comfortable margin)
- Jurist Pairwise: `threshold: > 0.5` — center_projected_1000 achieves 0.5275 (barely passes, 2.75pp margin)
- Jurivoc: `threshold: > 0.3` — center_projected achieves 0.43–0.47 (comfortable margin)
- Scale Stability: `threshold: > 0.95` — center_projected achieves 1.0000 (perfect)
- Boilerplate: `threshold: < 0.3` — ALL representations achieve 0.50–1.00 (systemic failure)

**Finding:** The Jurist Pairwise threshold (0.5) is **critically sensitive** — center_projected_1000 passes by only 2.75 percentage points, and the expanded slice fails. The Boilerplate threshold (0.3) appears **unrealistic for this corpus** — not a single representation approaches it. This suggests either:
- The boilerplate benchmark measures the wrong thing (language dominance ≠ procedural boilerplate), OR
- The threshold was set without empirical calibration on this corpus.

**The boilerplate resistance benchmark is methodologically flawed:** It uses "fraction of decisions with >80% same-language neighbors" as a PROXY for procedural boilerplate. In a multilingual corpus (de/fr/it), language clustering is EXPECTED and not equivalent to procedural boilerplate. The benchmark conflates language dominance with boilerplate dominance.

### 3.5 Boilerplate Resistance — Deep Dive

**Claim in Report:** "Procedural boilerplate dominates neighbor structure across all representations. This is a systemic challenge requiring architectural solutions."

**Reality Check:** The benchmark computes:
```python
# For each decision, count neighbors with same language
# If >80% of k=20 neighbors share language → "boilerplate_dominated"
boilerplate_rate = fraction_of_decisions_boilerplate_dominated
```

**This measures LANGUAGE CLUSTERING, not procedural boilerplate.** The Swiss Federal Court corpus has three languages (de=735, fr=403, it=62). Decisions in the same language naturally cluster because:
1. Legal terminology is language-specific
2. Citation patterns follow language
3. The embedding model (multilingual) may not perfectly align cross-language semantics

**Evidence:** Even signal_outcome_tfidf (which overclusters everything into near-identical vectors) achieves boilerplate=0.000 — not because it resists boilerplate, but because overclustering destroys language structure too.

**Finding:** The boilerplate resistance benchmark **does not measure what it claims to measure**. It is a language dominance proxy, not a procedural boilerplate detector. The "systemic failure" conclusion is valid for language dominance, but the label "boilerplate resistance" is misleading.

### 3.6 Jurivoc Hierarchy Alignment — Proxy Limitation

**Claim:** "NMI with legal_area (proxy for Jurivoc). Higher = better alignment with human legal taxonomy."

**Reality:** `legal_area` is a **court metadata field** (e.g., "Vertragsrecht", "Sachenrecht"), not the Jurivoc intellectual indexing system. The evaluation correctly labels this as a "proxy" and acknowledges: "True Jurivoc descriptors unavailable; legal_area used as proxy."

**Impact:** 
- legal_area signals naturally achieve high NMI with legal_area (tautological)
- center_projected achieves moderate NMI (0.43–0.47) without using legal_area
- The threshold (0.3) was likely calibrated on this proxy

**Finding:** **LIMITATION HONESTLY DISCLOSED.** The benchmark measures alignment with court metadata categories, not true Jurivoc descriptors. This is a known dependency (corpus limitation), not an evaluation flaw.

**The evaluation lane v3 work is genuinely complete for its scope.** The identified limitations should be addressed in future cycles (v4+), particularly: redesigning the boilerplate benchmark with actual procedural text detection, calibrating adversarial thresholds on held-out data, and obtaining true Jurivoc descriptors.
