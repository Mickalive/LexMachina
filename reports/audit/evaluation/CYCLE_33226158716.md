### 2.5 Boilerplate Resistance — **CRITICAL DEFECT**

#### 2.5.1 Test Code Threshold Bug
File: `evaluation/tests/boilerplate_resistance.py` (line 157) and `evaluation/run_center_projected_boilerplate.py` (line 235):
```python
status = BenchmarkStatus.PASSED if resistance_score > 0.6 else BenchmarkStatus.FAILED
```

**Metric definition:** `resistance_score = 1 - cosine_similarity(original, perturbed)`
- High cosine similarity (embeddings stable) → **Low** resistance_score
- Low cosine similarity (embeddings change) → **High** resistance_score

**Correct interpretation:** We want embeddings to be **stable** under boilerplate perturbation → **Low resistance_score is better**.
- TF-IDF baseline: resistance ~0.3-0.4 (boilerplate changes embedding)
- Good legal embeddings: resistance ~0.01-0.05 (boilerplate has minimal effect)
- **PASS threshold should be: resistance_score < 0.3**

**Code has it INVERTED:** PASS if resistance_score > 0.6 (i.e., embeddings CHANGE a lot).

#### 2.5.2 Actual Results vs Code Threshold

| Variant | resistance_score (1-cos) | Code Threshold (>0.6) | Correct Threshold (<0.3) | Saved Status |
|---------|-------------------------|----------------------|--------------------------|--------------|
| TF-IDF (sachverhalt) | 0.018 | FAIL ✓ | PASS ✓ | FAILED |
| TF-IDF (erwaegungen) | 0.017 | FAIL ✓ | PASS ✓ | FAILED |
| TF-IDF (full_text) | 0.017 | FAIL ✓ | PASS ✓ | FAILED |
| multilingual-e5-small | 0.004 | FAIL ✓ | PASS ✓ | FAILED |
| paraphrase-MiniLM | 0.016 | FAIL ✓ | PASS ✓ | FAILED |
| xlm-roberta-base | 0.00007 | FAIL ✓ | PASS ✓ | FAILED |
| **center_projected** | **0.050** | **FAIL** | **PASS** | **PASSED** ❌ |

**Finding:** The `center_projected_boilerplate_resistance.json` shows `"status": "PASSED"` with resistance_score=0.050, which **contradicts the code's own threshold** (0.050 < 0.6 should be FAILED). This indicates either:
- The test was run with a different/fixed version of the code not in the repo, OR
- The result file was manually edited after the run

The team's verification report correctly interprets the metric (PASS if < 0.3) but the saved artifact has an inconsistent status field.
