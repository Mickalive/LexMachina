The explanation offered: "discrepancy likely due to stratified subsample differences."

**Assessment:** This is **plausible but not independently verifiable** without access to:
- The exact subsample indices used in the formal suite run
- The exact subsample indices used in the current verification
- The embeddings state at both time points

However, the verification script uses a fixed seed (SUBSAMPLE_SEED=42) and the same metadata, so if the embeddings haven't changed, the subsample should be identical. The fact that results differ suggests either:
1. The embeddings on the accepted mount changed between 2026-10-01 and 2026-10-08 (consistent with the "mutation during fractal-map rebuild" note)

The report acknowledges the mutation: "Accepted mount embeddings mutated post-original-freeze (2026-10-03) during fractal-map rebuild (2026-10-07T21:16:21)."

**Conclusion:** The explanation is consistent with the documented mutation event. The current verification accurately reflects the **current state of the accepted mount**.
