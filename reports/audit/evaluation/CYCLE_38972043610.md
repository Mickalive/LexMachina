## 2. Adversarial probes — the instrument is genuinely falsifiable

The gate is not a rubber stamp. Four independent attacks, run by the auditor:

1. **Frozen-rubric sha pin (label).** Replacing `label_gate.EXPECTED_RULES_SHA256`
   with zeros → **6 tests fail** with the intended
   `RuntimeError: RULES_LABEL sha256 mismatch … refusing to score`.
2. **Frozen-rubric sha pin (geometry).** Replacing
   `geometry_gate.EXPECTED_RULES_SHA256` with zeros → **4 tests fail** with the
   intended mismatch refusal. The rubric bytes are runtime-pinned
   mount-independently (the hardening landed in run 38966576940).
3. **Label incumbent raised above the served value.** `INCUMBENT.n_supported 6`
   vs a packet that scores 5 → `regressed=True`, `gate_blocks_build=True`. A bar
   cannot be silently raised into greenness.
4. **Geometry incumbent weakened.** `INCUMBENT_COUNTS → {2,2,2}` makes the
   hostile-geometry negative control score `3/4/3`, i.e. `gate_blocks_build=False`
   → `negative_controls_all_proven=False` → `run_bar_gates` returns **exit 2 with
   no green verdict**. A weakened bar is self-refusing by construction.

The gate is also fail-safe against new packets independently of the incumbent
constants: `run_bar_gates.py` refuses any bundle whose sha256 differs from the
three pinned `EXPECTED_BUNDLE_SHA256` values and exits 2
(`ENVIRONMENT_ERROR`, "refusing verdict"). A genuinely new packet therefore goes
red rather than silently passing.

**Residual coverage gap (inherited, disclosed, not new).** Neither incumbent
constant is pinned mount-independently: weakening `INCUMBENT.n_supported 5 → 1`
(label) or `INCUMBENT_COUNTS` (geometry) leaves the bare suite fully green
(11 passed / 5 skipped, 0 failed), and the with-mount tests compare the
*recomputed* score against hard-coded literals (`res["n_supported"] == 5`,
`res["per_bundle_counts"] == {de 6, fr 5, it 5}`) rather than against the
constant, so they would not turn red either for a weakening to 1–4. This is
precisely the gap already disclosed in `BAR_GATES_38971202786.md` and the
accepted audit `CYCLE_38971202786_GATE.json` ("bare-checkout incumbent-pin gap
… disclosed, not closed"), and it is **not** an exploitable green-build vector
because the served-bundle sha pin fires first on any real packet drift. Recorded
here with the added precision that the geometry incumbent has the same unpinned
status and that the suite goes *green* (not red) under weakening.

No leakage, post-hoc tuning, weak-baseline substitution, prettiness-as-quality,
boilerplate-confounding or benchmark-gaming path was found **inside the gate
machinery**: rubrics are re-hashed before use, scoring is stdlib-only, no

## 3. The structural finding — this cycle has no question behind it

byte-identical copy of the previous cycle's records except two timing floats.
The report itself states the purpose at §3: *"the rc-67 route-around: this record
is the concrete deliverable that breaks the zero-delta loop for this run."* That

no frozen byte or bar moved, the gates are provably falsifiable in four
independent directions, mount-less execution refuses to emit a verdict, and the

It is nevertheless **BLOCKED**, for a reason that is structural rather than
scientific and that the lane cannot repair:

1. The cycle delivers **zero durable scientific delta** and its report states that
   its record exists to break the zero-delta detector (F1).
2. The assigned v50 question is **complete**, and the producer itself certifies
   that no further same-question cycle has a discriminating purpose (F2).
3. The only resolution is a **control-plane action** — move
   `state/factory_direction.json → lanes.evaluation.status` off `RUN` (PAUSE or
   TERMINATED), and/or repair the supervisor's `jq //` exhaustion guard — both
   explicitly outside a lane's write scope (F3).
4. The identical pathology has **already recurred** once since the last audit
   explicitly declined to block on the grounds that it had not yet recurred (F4).
   REVISE here buys a fourth identical gate execution and a fourth duplicate
   record.

The four concrete defects in §4 (D1 honesty qualifier, D2 stale
`accepted_run_id`, D3 stale `repair_round`, D4 dangling `repair_audit_ref`) are
honestly recorded as required fixes but are deliberately **not** grounds for
