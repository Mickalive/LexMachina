## 4. Adversarial Benchmark Validity

### 4.1 Language Dominance Test (PASS — well-designed)

- **Method:** k=20 NN (cosine), measure fraction of neighbors sharing query language
- **Threshold:** < 0.85 (lower = better)
- **Rationale:** Language should not dominate nearest neighbors
- **Audit:** Correctly implemented. The threshold is permissive (0.85) — most representations pass. This is appropriate for an adversarial gate.

### 4.2 Jurist Pairwise Preference (PASS — well-designed)

- **Method:** For each decision, check top-10 for:
  - Legal-relevant neighbor: same branch, different language
  - Language artifact: same language, different branch
- **Simulated jurist** prefers legal-relevant if available; forced to pick language artifact if only that exists
- **Threshold:** legal_neighbor_rate > 0.5
- **Audit:** Correctly implemented. This is a **strong adversarial test** — it directly measures whether the embedding space surfaces legally-relevant cross-language neighbors over same-language procedural neighbors.

**Critical finding reproduced:** `center_projected_768` (768-dim) fails jurist pairwise (0.4912) while `center_projected_64dim` passes (0.5121). This confirms the product lane finding that dimensionality reduction to 64 dimensions is critical for legal relevance.

### 4.3 Jurivoc Hierarchy Alignment (PARTIAL — proxy metric)

- **Method:** KMeans clustering at 4 clusters (Level 0 = branches) and 16 clusters (Level 1 = legal areas); NMI with branch/legal_area labels
- **Limitation:** Uses `branch` and `legal_area` metadata as **proxies** for true Jurivoc codes. True Jurivoc hierarchy is not available for all 1,200 decisions.
- **Threshold:** Level 0 NMI > 0.3, Level 1 NMI > 0.2
- **Audit:** The proxy is reasonable given data constraints, but **claims about "Jurivoc alignment" should be qualified as "branch/legal_area alignment."** The dramatic improvement for new representations (0.63–0.74 vs 0.06 for baseline) is real but measures alignment with court metadata, not the full Jurivoc taxonomy.

### 4.4 Scale Stability (PASS — reasonable)

- **Method:** 80/20 random split (seed=42), frozen PCA fit on full corpus, measure top-10 neighbor overlap for test points
- **Threshold:** mean overlap > 0.5
- **Results:** All representations 0.70–0.72 — good stability, no concerning differences
- **Audit:** Correctly implemented. The frozen PCA approach is appropriate.

### 4.5 Boilerplate Resistance (PARTIAL — proxy metric, correctly interpreted)

- **Method:** Compare neighbor types in top-10:
  - Boilerplate neighbors: same chamber, different legal_area (procedural similarity)
  - Legal neighbors: different chamber, same legal_area (substantive similarity)
- **Metric:** `resistance_score = legal_rate - boilerplate_rate` (positive = good)
- **Threshold:** > 0 (PASS)
- **Results:** **All representations FAIL** (scores -0.89 to -0.92)
- **Audit:** 
  - ✅ The metric is correctly interpreted (previous versions had inverted threshold)
  - ✅ The systematic failure across ALL representations is honestly reported as a "systematic limitation of current embedding approaches"
  - ⚠️ Uses `chamber` + `legal_area` as proxy for procedural vs. substantive content — not true boilerplate injection test
  - ⚠️ The v3 harness notes: *"Full decision text not available in expanded slice metadata. Requires corpus text for perturbation test."*
  - The separate v3 boilerplate resistance test (run 33221325181) with actual text perturbation showed **high resistance** (cosine similarity 0.95–1.0 after injection). The discrepancy arises because the two tests measure different things. This is **not a contradiction** but a limitation of the proxy.

### 4.6 Cross-Language Retrieval (PASS — meaningful threshold)

- **Method:** For each decision, measure recall@10 of same-branch, different-language decisions
- **Threshold:** > 0.2 (at least 1 in 5 cross-language equivalents in top-10)
- **Results:** Baseline fails (0.156), all 4 new representations pass (0.208–0.236)
- **Audit:** Meaningful multilingual capability test. Threshold is low but reasonable for a first gate.

### 4.7 Fractal Quality (PASS — uses hierarchical Leiden)

- **Method:** Hierarchical Leiden (coarse_res=0.5, sub_res=3.0) with coarse→fine purity improvement rate
- **Results:** All passing representations show improvement rates 59.6%–73.8%
- **Audit:** Correctly uses the project's fractal-map library. `hybrid_v2_epoch3` shows slight negative hierarchical advantage (-0.28%) — honestly reported.
