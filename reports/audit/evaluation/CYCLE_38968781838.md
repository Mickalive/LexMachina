(`tests/evaluation/test_frozen_bar_gates.py` lines 195–197) and
`state/evaluation.json → continue_recommended_reason` ("now demonstrably

| frozen qid `fr-bail-entretien`, reduced population (the test's own case) | `NOT_APPLICABLE`, 3 scored, no block ✅ | `NOT_APPLICABLE`, count 4, no block ✅ |

| frozen **anchor** qid outside the served lineage (`kuendigung-mietrecht`) | scores (`NOT_APPLICABLE`) | **`ValueError`** (lexicon only exists for the 3 served bundles in `RULES_GEOMETRY.inputs`) |

The geometry refusal is not an accident — it is a deliberate, already-pinned
behaviour: `test_geometry_unknown_bundle_refuses_invented_lexicon` (line 106,
pre-existing) asserts `pytest.raises(ValueError)` for an unknown qid. The new
test's headline claim therefore contradicts a sibling test in the same file.
What the test *actually* proves, and what is genuinely useful, is narrower:
**a packet built from a frozen anchor qid at a non-incumbent population is
scored and reported with `NOT_APPLICABLE` and does not spuriously block the
build.** Admitting a genuinely new product packet additionally requires a
deliberate, disclosed rules re-freeze (new anchor/lexicon/language entries) —
exactly the "nobody owns the BAR" work the claim pretends is already closed.

This is the same claim family as the 38964129305 REVISE (a verification claim
that exceeded what was verified), which makes it worth stating plainly: the
repair is a scope correction plus, optionally, one extra pin — not a rebuild.
It is concrete, small and same-cycle, so REVISE, not BLOCKED (see §7).
