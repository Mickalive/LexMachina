## 4. Critical Discrepancy: 64-dim vs 768-dim Center Projected

**This is the most material finding of the audit.**

| Aspect | v3 (64-dim PCA) | v6 (768-dim raw) |
|--------|-----------------|------------------|
| Embedding source | `center_projected_full/embeddings_center_projected.npy` (64-dim, PCA output) | Same file but treated as 768-dim? Wait — need to verify |
| Jurist pairwise | **0.5121 (PASS)** | **0.4912 (FAIL)** |
| Language dominance | 0.7660 (PASS) | 0.7738 (PASS) |
| Jurivoc hierarchy sep | 0.1128 (PASS) | 0.0956 (PASS) |

**Root cause investigation:** The v6 script loads `embeddings_center_projected.npy` from legal-distance v5 which is **768-dim** (the center_projected layer output before PCA). The v3 evaluation used the **PCA-reduced 64-dim version** (after `TruncatedSVD(n_components=64)` in the frozen pipeline).

The v6 script's `run_frozen_scale_benchmark` projects to 64-dim for scale testing, but the **adversarial benchmarks run on the raw 768-dim embeddings** (see line 550: `run_adversarial_benchmarks(emb, aligned_metadata, name)` where `emb` is 768-dim for baseline).

**AUDIT VERIFICATION:** 
- v3 results show `embedding_dim: 64` throughout
- v6 baseline results show `embedding_dim: 768` 
- v6 scale stability shows `representation_shape: [N, 64]` because `run_frozen_scale_benchmark` applies frozen PCA
- But adversarial benchmarks (language dominance, jurist pairwise, Jurivoc) run on **768-dim raw embeddings**

**CONCLUSION:** The evaluation correctly identifies this as a critical discrepancy. The fractal-map and product MUST use the 64-dim frozen PCA version validated in v3, not the 768-dim version evaluated in v6.
