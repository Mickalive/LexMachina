## 4. Code Inspection

### 4.1 Zoom Coherence Benchmark: Representation-Independent (DOCUMENTED)

**Location:** `run_cycle_7.py` line 433-530, `bench_zoom_coherence()`

The zoom_coherence benchmark loads pre-computed results from a single file:
```
/tmp/lex_accepted/fractal-map/results/fractal_map/evaluation/zoom_coherence_results.json
```

This file is representation-independent — it tests the fractal-map architecture, not individual representations. Consequently, **all 10 representations produce identical zoom_coherence scores** (improvement_rate=1.0, 12 improvements, 0 deteriorations).

**Impact:** The zoom_coherence benchmark cannot discriminate between representations. It validates the fractal architecture hypothesis (zoom reveals coherent substructure) but does not contribute to representation selection. The report correctly notes "all representations pass" but should clarify that this is an architectural validation, not a per-representation metric.

**Severity:** Low. The benchmark is valid for its intended purpose (testing fractal architecture). The report's presentation is slightly misleading by listing identical scores per-representation, but the underlying logic is correct.

### 4.2 Clustering Metric Inconsistency (KNOWN, MEDIUM)

**Location:** `run_cycle_7.py` line 386-394, `bench_legal_area()`

Cycle 7 uses `AgglomerativeClustering(n_clusters=n_clusters)` with sklearn defaults (Euclidean/Ward). Cycle 5 explicitly set `metric="cosine", linkage="average"`. This produces different cluster assignments.

**Impact:** Cross-cycle NMI/purity values are not directly comparable. Cycle 7 results are internally consistent but cannot be compared to cycle 5 baselines.

**Severity:** Medium. Already documented in state file. Does not affect cycle 7 internal validity.
