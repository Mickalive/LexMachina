## Independent Recomputation & Verification

### 1. Root Cause Analysis Verified

**Issue:** The `create_stratified_subsample()` function grouped decisions by `(branch, language)` and iterated over `groups.items()` for proportional sampling. In Python 3.7+, `dict.items()` preserves **insertion order**. When the control plane mount updated `metadata_174k.json` at **2026-10-08T23:40**, the decision ordering changed → group insertion order changed → `groups.items()` iteration order changed → random sampling sequence changed even with `np.random.seed(42)`.

**Three stable states observed (same embeddings, same config hash, same seed=42):**

| Metadata State / Run | Reps PASS Both Gates | Production Baseline JP | Date |
|---|---|---|---|
| NEW metadata (07:32 run) | 6/8* | 0.5925 | 2026-10-09T07:32 |
| NEW metadata (03:54 run) | 7/8 | 0.702 | 2026-10-09T03:54 |
| **FIXED (deterministic, 08:12+)** | **7/8** | **0.659** | **2026-10-09T08:12+** |

*Note: 07:32 run shows 6/8 PASS with different subsample composition (regeste_tfidf FAIL at JP=0.403, production baseline JP=0.5925), confirming non-determinism.

**Fix:** Sort `groups.keys()` by `(branch, language)` tuple before sampling, ensuring deterministic iteration regardless of metadata JSON ordering.

### 2. Fix Implementation Verified

`evaluation/verify_frozen_baseline.py` correctly modified:

```python
# BEFORE (non-deterministic):
for key, group_indices in groups.items():
    n_sample = max(1, int(len(group_indices) * size / total_valid))
    ...

# AFTER (deterministic):
for key in sorted(groups.keys()):  # Sort by (branch, language) tuple
    group_indices = groups[key]
    n_sample = max(1, int(len(group_indices) * size / total_valid))
    ...
```

**Files fixed:** ✅ `verify_frozen_baseline.py` (primary script)
