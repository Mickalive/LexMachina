## 3. Attack Surface

### 3.1 Over-Collapsing Labels to Artificially Inflate Purity

**Checked.** The normalization map (91 entries, 30-31 groups) merges only clearly-equivalent cross-language pairs (e.g., Strafprozess = Procédure pénale = Procedura penale). Coarse umbrella labels (public, civil, tax, social_insurance, administrative, criminal, NONE, economy) pass through unchanged. Tests verify distinct topics remain distinct (Familienrecht != Vertragsrecht, Invalidenversicherung != Unfallversicherung). **No over-collapsing detected.**

### 3.2 Post-Hoc Hypothesis / P-Hacking

**Checked.** The hypothesis and success rule (>=20% improvement) are declared in the script docstring BEFORE execution. The script saves results to JSON atomically. Two of three metrics barely clear 20% (20.2% and 22.3%); the third fails at 14.8%. The honest "PARTIALLY REFUTED" verdict and the explicit caveat that normalization does NOT flip benchmarks to PASS (<0.7 threshold) demonstrate appropriate hedging. **No p-hacking detected.**

### 3.3 NMI Decrease as Counter-Signal

**Noted and acceptable.** Hierarchy NMI drops from 0.5218 to 0.4881 with normalization. This is expected: NMI is sensitive to the number of classes, and reducing from 105 to 54 labels reduces the mutual information ceiling. The report includes this in the detailed results table without suppression. Purity (the primary metric) is what the success rule targets. **Not a defect.**

### 3.4 Zoom Improvement_pct Worsening

**Noted and acceptable.** Zoom improvement_pct goes from -50.6% to -54.4%. This is because both coarse and fine purity improve, but coarse improves more (0.029->0.039, +32.6%) than fine (0.014->0.018, +22.3%), widening the ratio. The success rule uses absolute fine_purity, not improvement_pct. **Not a defect.**

### 3.5 Label Count Discrepancy Across Documents

**Cosmetic defect identified.** The state/evaluation.json claims "unique_labels_raw": 108, and the report executive summary says "108 -> 55". However:
- Actual count of all unique raw labels (metadata): 105
- Actual count after filtering valid (non-unknown): 104
- v17 results JSON reports raw_unique_labels: 105
- v17 benchmark run reports num_unique_labels: 104

The "108" is a factual error in the state JSON. The reduction is 105->55 (47.6%), not 108->55 (49%). The report's "-49%" is slightly overstated. This is cosmetic and does not affect the core comparison, which operates on the benchmark-level counts (104->54). **Not material.**

### 3.6 Data Leakage

**Checked.** The normalization map is hand-crafted from external knowledge of Swiss legal terminology, not learned from the evaluation data. The same map is applied to all representations. No information from the normalized evaluation leaks into the normalization map construction. **No leakage.**

## 4. Hypothesis Verdict

The v17 hypothesis states: "Cross-lingual legal_area label normalization materially improves hierarchy-family purity on identical embedding+machinery, refuting the v16 'pure data granularity' attribution."

**Verdict: SUPPORTED (with nuance).** The v16 attribution that the hierarchy-family FAIL was caused by "105 unique legal_area labels...making cluster purity mathematically unlikely" is a mis-diagnosis. The dominant cause is un-normalized cross-lingual label duplication (105->54 valid labels, -48.1%). Normalization improves all three purity metrics on identical machinery. However, normalization alone does NOT flip benchmarks to PASS (hierarchy purity 0.389->0.467, still < 0.7 threshold), so residual fine granularity and coarse umbrella labels still contribute. The report's "PARTIALLY REFUTED" characterization is honest and appropriate.

## 5. Product Decisions

The following product decisions are supported by this evidence:
1. Corpus lane should normalize legal_area labels (de/fr/it -> canonical concept) before hierarchy-family benchmarks are judged.
2. Evaluation spec should define normalized label input for hierarchy_coherence/zoom_coherence/legal_area_clustering.
3. Fractal-map hierarchy quality is NOT refuted by v16 raw numbers.
4. linear_hybrid05_concat integration as COMBINATION map mode is reinforced/unchanged (it benefits most from normalization: +24.0% hierarchy, +27.7% zoom fine).

No repairs required. Safe to integrate.
