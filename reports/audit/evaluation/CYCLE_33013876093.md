## 3. Fix Verification

### 3.1 Boilerplate Resistance Test — **FIXED ✅**

**Prior defect:** `_measure_boilerplate_sensitivity()` returned hardcoded `0.5`; `_inject_boilerplate()` created perturbed text but never passed it to representation function.

**Fix implemented** (`evaluation/tests/boilerplate_resistance.py`):
- Added `_build_text_embedding_fn()` training TF-IDF vectorizer on corpus
- Modified `run()` to embed both original and perturbed text via TF-IDF
- Resistance score = 1 - mean(cosine_similarity)
- Baseline documented: TF-IDF ~0.35, SBERT/Legal-BERT ~0.5-0.7, target >0.7

**Verification:** Test now measures actual perturbation. Cosine similarities 0.84-0.92 confirm TF-IDF sensitivity to boilerplate injection. Resistance score 0.1402 correctly FAILS (threshold 0.6). This is an **honest negative result** — the test works and correctly detects that TF-IDF on synthetic text is not boilerplate-resistant.

**Minor concern:** The baseline of 0.35 is an asserted calibration point, not an empirically measured baseline from a separate TF-IDF run on real legal text. The `baseline_note` says "TF-IDF embeddings on synthetic legal text: resistance ~0.3-0.4" but the actual measured value is 0.14. This discrepancy should be resolved in the next cycle with empirical baselines from real corpus.

### 3.2 Multilingual Coverage — **FIXED ✅**

**Prior defect:** Only 1 multilingual docket found vs ~50 expected. Root cause: `docket_number` missing from `ground_truth.decision_metadata`.

**Fix implemented** (`evaluation/data/synthetic.py:378`): Added `"docket_number": d.docket_number` to `get_ground_truth()` output.

**Verification:** 50 multilingual dockets found, 150 cross-language pairs. Cross-lang mean similarity 0.3973 (baseline random: 0.15). Separation from same-lang: 0.3818 (>0.1 threshold). Status: **FAILED** (threshold 0.7) — correctly negative. Synthetic embeddings have independent noise per language version, so parallel versions are not aligned. Test correctly detects lack of cross-language alignment.

**Note:** The 0.3973 similarity is above random (0.15) because parallel versions share the same Jurivoc descriptors and legal area, so their embeddings are both pulled toward the same concept centers. The independent noise prevents perfect alignment.

### 3.3 Baseline Calibration — **FIXED ✅**

**Prior defect:** All baselines were hand-set constants without calibration source.

**Fix implemented:** All 5 test files updated with `baseline_note` fields documenting:
- Neighbor relevance: "Random embeddings: AUC-ROC = 0.5 exactly. TF-IDF on legal text: ~0.6-0.7. Legal-BERT/SBERT: ~0.8-0.9."
- Multilingual: "Random embeddings: cosine ~0. Naive multilingual: ~0.15-0.25. LaBSE: ~0.8+."
- Stability: "Static pre-computed: drift ~0. Retrained TF-IDF/SVD: ~0.3-0.5. Target: <0.3."
- Hierarchy: "Random clustering purity ~1/num_clusters (~0.1-0.2). Legal embeddings: ~0.5-0.7."

**Verification:** All baseline_comparison objects now include `baseline_note` with calibration references. This meets the requirement for documented baselines.

## 4. Critical Analysis of Results

### 4.1 Tautological Passes (Known Limitation, Honestly Reported)

Three benchmarks pass **only because the synthetic embeddings are oracle embeddings constructed from ground truth**:

| Benchmark | Why Tautological |
|-----------|------------------|
| neighbor_relevance | Embeddings built from Jurivoc centers; weak supervision pairs derived from same Jurivoc assignments |
| corpus_stability | Static pre-computed embeddings never change; `corpus_subset` parameter ignored by oracle fn |
| hierarchy_coherence | Embeddings constructed from Jurivoc centers; clustering recovers the structure used to generate them |

**Assessment:** This is **correctly and explicitly documented** in both the repair report and state file. The producer does not claim these results transfer to learned representations. The claim ceiling remains: *"Evaluation infrastructure executes and discriminates on synthetic oracle data."*

### 4.2 Honest Negative Results (Strength)

Two benchmarks fail **as expected** given the synthetic oracle design:
- **Boilerplate resistance** (0.14 vs threshold 0.6): TF-IDF on synthetic text is sensitive to boilerplate injection
- **Multilingual invariance** (0.40 vs threshold 0.7): Independent noise per language prevents alignment

The framework **correctly discriminates** — it passes where the oracle construction guarantees the property, and fails where the oracle construction lacks it. No benchmark weakening detected.

### 4.3 Potential Issues Flagged

| Issue | Severity | Details |
|-------|----------|---------|
| `corpus_stability` ignores `corpus_subset` | Low (known) | Oracle representation_fn doesn't use corpus context; test measures mock stability. Honestly noted in state file. |
| Boilerplate baseline 0.35 vs measured 0.14 | Medium | Asserted calibration not empirically verified on this data. Next cycle should measure empirical TF-IDF baseline on real corpus. |
| Hierarchy has identical clusters at all 3 levels | Low | All 3 levels show 46 clusters with identical metrics. `hierarchy_consistency=1.0` because children = parents (flat hierarchy). Agglomerative clustering with fixed n_clusters per level doesn't create nested structure. |
| Multilingual threshold 0.7 based on external LaBSE | Low | Not an empirical baseline from this system. Acceptable for exploratory tier. |
