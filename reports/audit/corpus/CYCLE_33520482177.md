## 4. Recurring Defect Analysis

**This is the 4th recurrence of the identical field_coverage fabrication defect:**

| Cycle | Run ID | Fix | Delta |
|-------|--------|-----|-------|
| v14_repair_round2 | 33397008729 | 0.993→0.526, 1.0→0.505 | First fix |
| v17_repair_round1 | 33420652112 | Same correction | Recurrence 1 |
| v23_repair | 33435211349 | Same correction | Recurrence 2 |
| **v34_repair_round2** | **33520482177** | **Same correction** | **Recurrence 3** |

**Root cause:** Fresh workspace reproduction cycles (like v32) independently compute field_coverage from a local sample rather than loading `validation_report_v14.json`. The local sample produces inflated values (cited_decisions=0.993, outcome=1.0) because it may over-represent certain record types.

**Systemic issue:** There is no regression test that enforces field_coverage matches the canonical validation report at the state level. The v14_repair_round2 cycle added `test_field_coverage_matches_canonical()` to the test suite, but the test only validates against `bger_2024.jsonl` sample data (thresholds), not the canonical `validation_report_v14.json` exact values.

**Recommendation for permanence:** Add a test that loads `validation_report_v14.json` and asserts `state/corpus.json` field_coverage values match exactly, preventing any future regression.
