## Bugs & Issues Found

### BUG-001: Citation Normalization Strips `bge_` Prefix on Underscore Format
**File:** `corpus/acquisition/citation_resolver.py`, method `_normalize_ref`
**Severity:** Low (no practical impact today)
**Description:** `_normalize_ref("BGE_133_II_249")` returns `"133_ii_249"` instead of `"bge_133_ii_249"`. The prefix-stripping logic runs after lowercasing but before separator normalization, so `bge_133_ii_249` matches the `bge_` prefix and gets stripped.

**Impact:** If/when the corpus contains BGE references in underscore format (e.g., from Parquet), they would fail to match the normalized index key. Currently `bge_indexed=0`, so no effect.

**Fix:** Move prefix stripping to operate on original separators, or only strip when prefix is followed by space/standard separator.

```python
# Current (buggy):
s = text.strip().lower()
for prefix in ("bger_", "bge_"):
    if s.startswith(prefix):
        s = s[len(prefix):]
        break
s = re.sub(r"[\s/\-]+", "_", s)

# Fixed approach:
# Strip prefixes before lowercasing/separator normalization, or
# only strip if followed by space or standard BGE separator
```
