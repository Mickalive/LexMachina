## 3. Defect D-1 (MEDIUM) — false provenance: “dense 174k AUC = 0.482 FAIL”

**Locations (propagated into the control plane):**
- `reports/director/RUN_38040441141.md` lines **30, 75, 88, 159**
- `state/factory_direction.json` → `lanes.legal-distance.question`, `lanes.evaluation.question`, `director_note`

**Proposal asserts** (representative, report L75):
> “…All dense citation-heritage runs at 174k FAILED with *insufficient valid pairs*; the latest accepted evaluation gate records **dense 174k AUC = 0.482 FAIL**…”

**Accepted evidence contradicts this attribution:**

1. The 0.482 figure’s source artifact is `/tmp/lex_accepted/core/evaluation/results/evaluation/citation_heritage_174k.json` (`run_id citation_heritage_174k_1790199246`) with
   `"embedding": "cited_outcome_hybrid_0.5_174k"`, `auc_roc = 0.481957`, `n_positive = 804`, `n_negative = 1608`, `status = FAIL`.
   `cited_outcome_hybrid_0.5` is a **sparse TF-IDF + outcome hybrid** (the same family as the accepted frozen production representation `cited_decisions_tfidf_outcome_hybrid_0.5`). It is **not** a dense embedding.
2. The accepted evaluation audit records the row explicitly as the hybrid: `core/evaluation/reports/audit/evaluation/CYCLE_38037204821.md` L108 — “Citation Heritage AUC (**cited_outcome_hybrid_0.5_174k**) | 0.482 | ❌ FAIL”. Its companion dense row is “Citation Heritage AUC (**center_projected_64dim**) | 0.7922 | ✅ PASS (partial)”.
3. Accepted gate `CYCLE_35949306163_GATE.json` states plainly: *“Citation heritage FAIL on **TF-IDF** (AUC=0.482) correctly preserved as negative evidence; **dense embeddings required**.”*
4. Accepted gate `CYCLE_38008331991_GATE.json` lists *“full 174k dense BLOCKED”* as a negative result.
5. The accepted evaluation state (`evaluation.json` → `dense_embedding_complementary_acceptance_criteria.citation_heritage_view`) sets dense citation-heritage to `status = DENSE_NOT_EMPIRICALLY_VALIDATED_BLOCKED_ON_CITATION_GRAPH_COVERAGE`, `note = “All dense citation heritage runs at 174k scale FAILED with 'Insufficient valid pairs' … Previous claims of AUC 0.7667-0.8182 … are retracted.”` — i.e. **no dense 174k AUC exists.**

**Why this is a defect and not a nitpick.**
- It is internally self-contradictory: the same sentence says all dense runs failed with insufficient valid pairs (⇒ no dense AUC can be computed) *and* cites a dense 174k AUC.
- “Preserve provenance” is a Master-Prompt non-negotiable. Attributing a sparse-hybrid measurement to dense embeddings misstates accepted evidence.
- It sits in the **resumable lane question text** (`legal-distance`, `evaluation`), exactly where a downstream lane would look for a dense number to reproduce; the accepted state says no such number exists.
- It is the *same class* of error the F-1 repair was chartered to remove (unaccepted/mis-sourced evidence about citation-heritage provenance). Tracing the phrasing back, it originates in the prior audit’s own F-1 `repair_action` wording (“latest dense 174k AUC=0.482 FAIL”), which was itself imprecise; this audit corrects the record.

**Required repair (same-cycle, textual):** Replace every “dense 174k AUC = 0.482 FAIL” with an accurate statement, e.g.
> “The 174k citation-heritage run for the **sparse** `cited_outcome_hybrid_0.5` representation scored AUC 0.482 (FAIL; `citation_heritage_174k.json`, n_pos=804). **Dense** citation-heritage at 174k was **not measured** — all dense runs FAILED with *insufficient valid pairs* (`DENSE_NOT_EMPIRICALLY_VALIDATED_BLOCKED_ON_CITATION_GRAPH_COVERAGE`).”
and remove the self-contradiction. Apply to report lines 30/75/88/159 and the two lane questions + `director_note`.
