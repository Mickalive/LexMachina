## 2. F2 — the bundle had no reproducible identity

The advisory's cause ("last-bit differences, unpinned requirements") was
**measured, not assumed**, on the recorded claim query.

* Reproducing the cross-environment symptom locally: six replays of the same
  query out of the same committed cache — three with default hash
  randomisation, three with `PYTHONHASHSEED=0/1/2` — produced three different
  file sha256 values while the auditor had seen a fourth on another machine.
* Diffing two replays field by field: **five** fields vary and nothing else
  (`provenance.latency_seconds`, `provenance.timing.{local_total_s,
  upstream_retrieval_s, local_map_s}`, `provenance.retrieval.remote.latency_seconds`).
  Those are wall-clock measurements; the raw file hash therefore *can never*
  match across runs, which is a sharper statement of the same problem.
* Root cause of the *data* difference: `build_map` labelled clusters with
  `terms[np.argsort(-mean)[:5]]` over the whole 5000-term vocabulary. For a
  cluster of 1-5 decisions only a handful of terms have a non-zero mean, so the
  4th/5th label slots were filled from thousands of **exactly tied zero-mean**
  terms — i.e. from `argsort` internals, not from the data. The auditor saw
  exactly this (the four disputed clusters have sizes 5, 1, 1, 1).
  `_cluster_label` (the recompute-on-merge path) had the same shape, so the two
  paths could also disagree about the same cluster.

Repair (product-side, no data or benchmark touched):

* `product/query/qmap.py::label_terms` is now the single ranking used by both
  the initial fit and the merge path. It admits only terms with `mean > 0` and
  orders them by `(-round(mean, 9), term)`.
* Consequence, measured on the claim bundle: no label names a term that is
  absent from its cluster any more. Before, `C6` read
  `ptt, betriebe, unterstehen, zugefügt, privatrecht` for a **one-decision**
  cluster — four of those five terms occur nowhere in that decision. It now
  reads `ptt, betriebe, benützern, betrieben, beurteilt`.
* `product/replay_bundle.py::content_sha256` is the new reproducible identity:
  sha256 over the bundle with exactly the five re-measured timing paths
  removed. Two replays under different `PYTHONHASHSEED` values now agree on it
  (`6b5a08b0…`) while their file hashes differ — the difference is measurable
  and is *only* the wall clock.
* `product/tests/test_relations_and_labels.py::test_cluster_label_is_stable_under_last_bit_float_noise`
  perturbs every cluster mean at 1e-16 relative, 25 times, and requires an
  unchanged label. That is the advisory's property as an executable test.

## 3. F3 — the map could not show any relation at all

`relations` were produced only by `find_citations` string matching over
decision bodies. 30 of the claim bundle's 154 rows are unhydrated citation
shells with no text, so the map's "reveal relations on selection" affordance
(QUERY_MAP_MVP §7) rendered empty for the whole query.

The OpenCaseLaw `/citations` channel already returns **typed** edges and the
accepted adapter records each one on the candidate row's `provenance_events`
(`seed_decision_id`, `direction`, `confidence`, `mention_count`). It does not
surface them as bundle relations, and `frontier/**` is outside product write
scope — so the product recovers them:

* `product/query/pipeline.py::typed_citation_relations` rebuilds each edge with
  one reading direction (`source` cites `target`: an `incoming` row is a
  decision citing the seed, an `outgoing` row is a decision cited by the seed),
  emits an edge only when **both endpoints are on the map**, and de-duplicates.
* `_merge_relations` puts typed edges first and de-duplicates per decision
  *pair* (a pair arriving as both kinds is one line in the detail panel, not
  two), keeping the 500-edge cap.
* `provenance.relations_provenance` exports the counts and the provenance
  string, plus a claim ceiling: these are the upstream channel's own seed /
  direction records for this query, not a verified citation graph.
* `product/query/progressive.py` re-derives the edges in the expand stage, so a
  relation revealed only after expansion is not lost and an edge whose second
  endpoint never reached the map is dropped rather than dangling.
* `product/static/query.html` states the direction in the detail panel
  (`→ cite X` / `← cité par X`, with the upstream confidence) instead of a bare
  `↔`.
* `product/replay_bundle.py` refuses a dangling relation (new exit **7**, in
  the same family as the exit-4/5/6 guards) and `genuine()` now accounts for
  it.
