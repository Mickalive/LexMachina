## 1. D1 (material) — the test was measuring the wrong machine

**Finding.** `test_handoff_content_sha256_reproduces_via_the_product_own_hasher` used the
committed `bundle_path` as an **absolute** path. The shipped `handoff.json` / `packet.json`
embed `/home/runner/work/LexMachina/LexMachina/...`, so the test opened the producer's CI
workspace instead of the tree under test.

**Why it looked green here.** This checkout happens to sit at exactly that path. The defect only
appears on any other root — which is precisely the case an independent auditor runs.

**Reproduced, twice, before fixing:**

| sandbox tree | pre-repair test | correct? |
|---|---|---|
| `fr-bail-entretien` bundle altered 217 → 3 decisions | **PASSED** | no |
| `questions/` bundle files deleted outright | **PASSED** | no |

A content-hash guard that passes against deleted and altered content is not a guard. The test was
verifying that the producer's machine still had its files.

**Fix — in the test, never in the artifact.** `resolve_committed_path(raw, root=None)`
(`product/tests/test_v52_endgame_delivery.py`) re-roots a recorded path by taking its tail from
the `results` component and joining it onto the checkout under test. The **content-sha256
assertions are kept unchanged** — only the resolution moved. An unanchored path degrades to the
packet dir under the given root, never to an absolute read of some other machine's file.

**Verified.** Same tampered sandbox, post-fix:

```
FAILED ... fr-bail-entretien content hash drifted
 bc80d239eb9e68fd2c2f8b66ae3d2d322e883b94a468e0fbf70c2bda1658398a
 != d9c2f1919e572d01dd2af30edea2bef6f5d64d12d0f31d0bf98bc645e8fa0913
```

`test_resolve_committed_path_reads_the_tree_under_test` rebuilds that tamper shape in a temp root
so the old behaviour cannot return silently.
