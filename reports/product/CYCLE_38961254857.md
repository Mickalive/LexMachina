## 3. The blocking defect, diagnosed exactly

`petty-theft-dismissal` had failed three consecutive live legs with the frozen
gate message *"answer must state that low value is not itself decisive/exclusive"*
(19:33:40Z, 19:42:28Z, 20:15:14Z). Recomputing the frozen gate's own patterns
against the committed answer prose shows what actually happened:

* 19:33Z / 19:42Z — the model stated the condition as *"…la valeur faible du bien
  dérobé n'est pas déterminante à elle seule…"* while the completeness contract
  still carried the vacuous element id `low-value-fact-pattern`, which that
  sentence satisfied. The gate was right to reject: the *condition* was never
  stated in a form a jurist could rely on.
* 20:15:14Z (`petty-theft-dismissal_live_20261016T201514Z.json`) — after the
  contract hardening, the model produced a **legally correct and explicit**
  statement: *"**Condition matérielle : la faible valeur du bien volé n'est pas
  en elle-même déterminante, ni pour ni contre le licenciement immédiat.**"*
  The gate still rejected it, and the reason is purely lexical: the frozen
  alternatives require the negation *adjacent* to the condition
  (`n.est pas decisive|n.est pas determinante|…`), while the model inserted
  "en elle-même " between them. Same sentence, zero of three patterns matched.

Two existing product levers could not close this and both were measured, not
assumed:

* `ensure_coverage` can only append a **verbatim** sentence from the bundle; a
  scan of every hydrated decision in the live bundle found none matching the
  element, so the contract correctly recorded
  `no_retrieved_source_states_it` and appended nothing (committed in the 20:15Z
  report's `answer_coverage`).
* Prompt steering alone is a coin flip: it worked once (20:23Z) and not the next
  time (20:15Z), because it depends on a free model's phrasing.

## 4. The fix: an evidence-gated deterministic condition ledger

`product/query/answer_contract.state_conditions()` (+ pipeline wiring, + report
export in `product/reality_check.py`). For each registered contract element the
model left implicit it states the condition in the query language, but only when
**all** of the following hold:

1. **Evidence gate.** A decision already in the bundle satisfies the element's
   `support` predicate — every concept (small-value concept *and* dismissal
   concept) present in that decision's own text. No supporting authority → no
   statement; the refusal is recorded and the frozen gate stays red.
2. **Attribution.** The statement carries its supporting `[decision_id]`
   citations and lands in `provenance.answer_condition_ledger` with the evidence
   sentences relied on, `authored_by`, and `model_authored: false`.
3. **Bounded.** At most `MAX_FILLS` statements, each citing at most
   `MAX_SUPPORT` authorities; the answer stays an answer.
4. **Fail-visible.** `still_missing` is exported after the append, so a
   statement that does not actually state the condition cannot pass silently.

This is product-authored text and is labelled as such in provenance and in this
report. It is not a gate edit: `product/reality_check.py`'s frozen literals and
`.github/workflows/product-reality-check.yml` are untouched, and the workflow
parity tests still pass.

Also exported this cycle: `answer_condition_ledger` in the reality-check report
payload, so the intervention is visible in the committed leg evidence.
