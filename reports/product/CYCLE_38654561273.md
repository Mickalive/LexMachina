## 2. The audit's required fixes and what was done

### required_fixes[0] — cache-read time published as `upstream_retrieval_s`

> *"record per-sample retrieval provenance (cache_hits / network_calls from
> bundle.provenance.request_summary plus cache_stats), derive cache_state from OBSERVED
> cache/network state instead of 'index==0' (product/latency_budget.py line ~217), and stop
> presenting cache- or fixture-served time as upstream_retrieval_s (rename the field or add
> served_from: cache|network|fixture); correct the separation_rule/docstring text that currently
> asserts 'OpenCaseLaw network+adapter time'."*

**Code (`product/latency_budget.py`)**

| change | detail |
|---|---|
| `classify_served_from(bundle)` | `network` / `cache` / `mixed` / `fixture` / `unknown`, derived from `provenance.fixture_mode`, `provenance.request_summary.{network_calls,cache_hits}`, `provenance.cache_stats`; returns the evidence dict it used, incl. `basis` |
| `derive_cache_state(bundle)` | `cache_state` is now a *consequence* of the observation (`network→cold`, `cache→warm`, `fixture→fixture`, no evidence→`unknown`); the `index == 0` rule is deleted |
| per-sample provenance | every sample records `served_from`, `served_from_basis`, `request_summary{requests_logged,network_calls,cache_hits,failures}` and `cache_stats{hits,misses,writes,n_keys}` |
| field split | `retrieval_s` = raw retrieval-phase time whatever served it; `upstream_retrieval_s` is `None` unless `served_from == "network"` |
| aggregation guard | `UPSTREAM_ONLY_METRICS = {"upstream_retrieval_s"}` — network admissibility requires observed request evidence (`request_summary.network_calls > 0`); legacy index-derived ``cache_state`` labels are never trusted as network evidence. The `aggregate(..., predicate=upstream_admissible)` predicate filters from observed provenance, not from sample-internal labels. |
| unmeasured is a value | with no network-served sample the verdict carries `measured: false`, `p50/p95: None`, an explicit `UNMEASURED` note and a report warning |
| text | module docstring and `separation_rule` no longer assert "upstream_retrieval_s is OpenCaseLaw network+adapter time"; they state the network-only rule |
| `--refresh-first N` | records the first N samples with `retrieval_mode="refresh"` (network only) so one artifact can hold both a genuine upstream measurement and the warm cached-map budget |

**Artifacts** — `results/product/latency_budget/CYCLE_38649613677_live.json` is annotated **in
place and non-destructively** by `annotate_legacy_report()` (`--annotate-legacy`): the original
report survives byte-for-byte under `correction.as_recorded_report`, each sample keeps
`as_recorded_upstream_retrieval_s` / `as_recorded_cache_state` / `retrieval_s`, the upstream
claim becomes `None`, and `correction.any_sample_exercised_network` states plainly that **no
sample in that artifact ever touched the network**. Aggregates were recomputed over **all five**
samples (not just the four the old index rule called "warm"), so the budgeted numbers got
*more* conservative, not less: cached map p95 `0.3659 s → 0.4898 s`, local map p95
`0.0618 s → 0.212 s`, detail click unchanged — all still **PASS**.
