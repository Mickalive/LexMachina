## What was broken

The shipped fixture server (`python product/query_app.py --fixture`) could not
render three of the four frozen Swiss-law questions at its **default request**
(`/api/query/start?q=...`, `n=150`). The real OpenCaseLaw answers for those
questions were already committed in `results/product/query_cache`, but the
adapter cache key includes the search `limit`. The cache recorded the questions
at several page sizes (10/12/25/30/41/...), while the first-page pipeline
derives `page_size=37` from `n=150`. Exact-key replay therefore missed and the
endpoint returned `500 {"error": "RuntimeError: OpenCaseLaw retrieval returned
no decisions"}`.

This is a developer-facing vertical-slice failure: the canonical FAST MVP loop
is *question -> cached OpenCaseLaw result bundle -> source-linked clickable
map*, and the map was available on disk but unreachable for real questions.

## What changed

1. **`product/query/cache_replay.py` (new).**
   `QuestionMatchTransport` is an offline-only transport. It honours the exact
   cache key first. On a `/decisions` search miss it may serve a recorded page
   for the **same query text, language and non-paging params**, ignoring only
   `limit`. Different query, language, offset, sort or fields selection never
   matches. No network call, no cross-question substitution; the adapter still
   normalises, dedupes and ranks the returned records.
2. **`product/query/pipeline.py`.** `replay_fixture_query` gains a third,
   offline-only replay source after the canonical fixture scenario and the
   exact-live-config replay. It reads the caller's configured cache root
   (`cfg.cache_path()`), so test isolation is preserved. Provenance records
   `source=product_query_cache_question_match_replay`, the match counts and the
   narrow config-tolerance rule.
3. **`product/fixture_question_replay_probe.py` (new).** One-command offline
   smoke over the four frozen questions plus the German rent question; traps
   non-loopback `socket.connect`, writes a machine-readable artifact and
   fails closed if any map is empty/invalid.
4. **`product/tests/test_fixture_question_match_replay.py` (new, 21 tests).**
   Pins exact-first ordering, page-size matching, semantic-parameter
   non-matching, language/offset isolation, all four frozen questions at
   `n=150`, the German-rent regression witness, fail-closed unknown questions,
   and the shipped HTTP endpoint for every frozen question.
