## 1. What the lane asked, and what this cycle did

Direction v51 named the two owner-independent deltas as already delivered (session
finalizer, latency budgets) and left one milestone: the comparative human gate. The gate
is one owner session away, so this cycle removed the last thing standing between the owner
and a usable session — **the session began with 2.3 minutes of empty page.**

Measured on the shipped server before any change (live OpenCaseLaw, real free model,
query `Responsabilite penale de l'entreprise selon l'art. 102 CP`, `n=150`):

| request | wall | breakdown |
|---|---|---|
| `GET /api/query/start` | **136.79 s** | upstream OpenCaseLaw 136.61 s, local geometry 0.18 s |
| `GET /api/query/enrich` | **150.70 s** | model 101.69 s, evidence hydration 49.00 s |

The two-phase API was progressive in name only: `run_query_initial` still executed the
whole multi-channel retrieval (variants, DE/FR/IT pages, citation expansion, leading
cases, up to 40 upstream requests) before returning the first point. QUERY_MAP_MVP §9A
asks for the opposite — draw the first results immediately, expand toward 100–300 in the
background.

### Negative result (kept, not buried)

The previous audit recorded a defect: *"`ThreadingHTTPServer` hangs/crashes when
`/api/query/enrich` or `/api/query/run` invoke the generative audit."* **It did not
reproduce.** Driving the blocking path with a real model: 288 concurrent `/api/health`
probes, **0 failures**, server alive after enrich, answer ready, 7 citations. No crash-fix
was written because there is no crash to fix. The delivered change removes the blocking
itself, which is what actually makes the session workable.

## 2. What shipped (all product-owned paths)

### 2.1 First page, then background expansion — `product/query/progressive.py` (new)

* `run_query_first_page(...)` — one bounded adapter stage (`stages=("search",)`,
  `max_requests=1`, no citation/leading expansion) → local geometry → a **complete valid
  `query_result_bundle`**. Provenance declares it partial (`progressive.stage=first_page`,
  `expanded=false`, `target`).
* `expand_query_bundle(...)` — the full retrieval merged into that same bundle.
* `target_clusters(target)` — the first page uses the cluster count of the *finished* map.
  Without it the 38-decision first page capped the expanded 194-decision map at 4 clusters
  where the single-shot map had 8 (observed live this cycle).

### 2.2 A map that can grow without moving — `product/query/qmap.py`

`MapModel` / `fit_map_model` / `project_into_model` / `build_map(model=...)`: the
projection is fitted once and later decisions are projected into *that* space and attached
to their nearest existing cluster. The accepted `ocl_adapter` component was not modified.

Contract, enforced in `expand_query_bundle` and exported as
`provenance.progressive`:

* already-rendered points keep `x`, `y`, `cluster_id` **and `is_outlier`**;
* cluster **ids** stay stable; cluster **labels** are recomputed from merged membership
  (more evidence for "why this group exists", no move);
* `points_moved` (what the client saw) and `points_displaced_by_refit` (before the freeze
  restore) are both reported.

### 2.3 A job server that never blocks the browser — `product/query_app.py`

```
GET /api/query/start?q=&n=     -> first-page map + run_id, expansion job already running
GET /api/query/expand?run_id=  -> starts/queries the expansion job
GET /api/query/enrich?run_id=  -> 202 {status, poll} immediately (job)
GET /api/query/status?run_id=  -> progress for both jobs (polled every 1.5 s by the UI)
GET /api/query/bundle?run_id=  -> current bundle (resume after a reload)
```

* `ThreadPoolExecutor(max_workers=2)`; a job error is recorded on the run and **never**
  kills the server.
* Per-run job **dedup**: a double-click cannot start two three-minute model runs.
* Enrich waits for a running expansion (bounded 900 s) so the answer is never generated
  from the partial first-page candidate set.
* `&wait_s=<seconds>` keeps the blocking single-call form for scripts and CI.

### 2.4 UI — `product/static/query.html`

Three-stage progress ("Première page / élargissement / réponse"), live counts while
jobs run, `localStorage` run pointer and reload resume. The accepted
`lex_gate_switch.js/css` assets are untouched (still byte-identical, same hooks).

### 2.5 Evidence recorder — `product/slice_smoke.py` (new)

Drives the shipped server exactly like a browser (no fixtures, no pipeline shortcuts) and
writes `results/product/progressive_slice/<run>.json` + the full bundle.

§9A budgets: first map visible ≪ 1 s warm / 6 s cold; local map overhead 0.14 s + 0.06 s
(budgets < 1.5 s and < 2 s); cached map total < 1 s; detail click unchanged. Upstream
OpenCaseLaw time stays reported separately (cold first page 6.0254 s upstream; warm
0.0185 s cache read) and is never folded into local numbers.

### Defects this cycle found in its own code and fixed

1. **Answer loss on overlap** — an enrich started while expansion was running answered
   from the partial set, then the expansion replaced the bundle: the session ended with a
   map and no answer. Fixed (enrich waits, expansion preserves a ready answer); regression
   test added.
2. **15 rendered outliers re-flagged** by the merged refit. Fixed (frozen outlier status);
   regression test added.
3. **Cluster granularity capped** by the small first page (4 instead of 8). Fixed.
4. **Cluster labels frozen on 38 decisions** of evidence. Fixed by recomputing labels from
   merged membership while keeping ids stable.

## 5. Honest limits / claim ceiling

* The comparative human gate is **not** answered. This cycle makes it *survivable*; only a
  real owner/jurist session can pass it. `human_gate_ready` stays `false`.
* First-page size is one upstream page (≈38–50 hits for a real query). It is a real subset
  of the same retrieval, not a padded or fixture-derived map; the expansion is what
  completes it, and its provenance says so.
* `latency_budget.py` was not re-run: §9A numbers for this cycle come from the slice smoke
  artifact, which reports the same fields plus the first-page/expansion split.
* Fixture mode replays only the recorded fixture query (`Kündigung Mietvertrag Mietrecht`);
  a different query in `--fixture` mode legitimately returns no decisions.
