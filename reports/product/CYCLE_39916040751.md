## 2. D1 repair: null decision language

`results/audit/product/CYCLE_39909013473_GATE.json` required:

> Default decision.language to 'und' when null (5 decisions in fixture bundle
> have null language; breaks langFilter UI)

Reproduced on the inherited tree with the audit's own path
(`run_query_initial(..., retrieval_mode="fixture")` + `enrich_query_bundle(...)`):
the 100-row fixture bundle contained **5 null-language rows**
(`bge_BGE_118_II_50`, `ge_gerichte_ACJC_1891_2025`,
`ge_gerichte_ACJC_921_2026`, `ge_gerichte_ACJC_982_2026`,
`vd_gerichte_78f4c3e8-...`). Because `query.html` filters with
`d.language !== langFilter`, those rows were silently absent from every
language-specific view.

Repair:

- `product/query/pipeline.py::_candidate_to_product` normalises the row
  language: a plausible ISO-639 code (`de`, `fr`, `it`, `en`, `rm`, …) is
  lowercased and preserved; `None`, empty, numeric or junk values become
  `"und"`. No specific language is ever invented.
- `product/static/query.html` adds the `und` bucket to `langFilter` so the rows
  remain inspectable rather than unfilterable.
- `product/tests/test_language_normalization.py` adds **5 offline tests**
  covering the pure assembler, the fixture pipeline and the UI option.
