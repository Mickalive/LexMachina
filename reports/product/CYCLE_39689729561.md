## 2. The short-sha width (D2)

`git log --format=%h` is **not** a fixed width: git auto-scales the abbreviation
to the repository's size, so the same commit rendered as `3f94e0e` on the
machine that published the cache-rewrite attribution and as `3f94e0e8c` on the
git 2.55.0 build this cycle runs on. The consequence was that the committed
attribution artifact **did not reproduce from the committed tree**, which is the
binding defect class of this factory.

Both instruments now ask git for an explicit width:

* `product/cache_rewrite_attribution.py` — `git rev-parse --short=7`;
* `product/test_delta_attribution.py` — `git rev-parse --short=7`, with the
  commit subject and author date read separately.

The published artifact's **shape was deliberately not changed**, so the
historical artifact keeps its exact published form and now reproduces
byte-for-byte here: `python3 product/cache_rewrite_attribution.py --check`
exits 0 against
`results/product/cache_attribution/CYCLE_39674781875_manifest_rewrite_attribution.json`.
The rule lives in the tool, not in the prose that repeats it.
