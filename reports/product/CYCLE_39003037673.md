## 2. Obligation (1) — the accepted bars are a machine gate of packet admission

New module `product/query/packet_admission.py` reads the committed accepted
verdict snapshots and turns them into a hard admission gate:

- `results/product/frontier_verdicts/ACCEPTED_counter_label_38841035773__map_semantics_38846038296.json`
- `results/product/frontier_verdicts/ACCEPTED_frontier-served-packet-falsification_38880639079.json`

`assess()` is **fail-closed**: if neither accepted verdict snapshot is present it
returns `no_accepted_bar_verdict` and blocks. `enforce()` forces
`ready_for_owner_session=false`, and records `ready_for_owner_session_base`,
`packet_admission_blocked`, `packet_admission_reason` and the full
`packet_admission` payload. It is wired into:

- `gate_packet.finalize_summary(summary, n, mode, *, admission=None)` (the
  `admission=` kwarg is injectable for tests; production reads the committed
  snapshots), and
- `gate_packet.recheck_packet(...)`, and
- `gate_packet.owner_card(...)`, which now prints a prominent
  **STANDING DO-NOT-SERVE ORDER — this packet is NOT owner-ready** banner with
  the blocking reason, so an owner can never be shown a per-question READY card
  without also seeing the machine hold.

Verified blocking reason on the served packet:

```
counter_label_support 5/65 = 0.0769 < frozen absolute bar 1.0;
map_geometry 0/3 bundles pass all 11 criteria
```

Tests: `product/tests/test_packet_admission.py` (12) plus two new
`test_gate_packet.py` cases (the owner-card banner fires when blocked and stays
absent when admission is allowed) plus the updated
`test_finalize_summary_handles_the_all_pass_live_case` (base roll-up true,
admission denies; positive control with an injected admitted admission proves the

## 3. Obligation (4) — accepted geometry component integrated in the promotion cycle

- **Vendored**: `product/vendored/qmap_geometry/` is a byte-identical subset of
  the accepted package (`__init__.py`, `geometry_core.py`, `hydration.py`,
  `variants.py`, `vendored/frontier_map_semantics/{__init__.py,textgeo.py}`).
  `PROVENANCE.json` records the per-file sha256, the accept commit `be5eba7f`,
  the promoted variant, and the frozen geometry rules digest `a7452748...`.
- **Seam**: `product/query/qmap_variants.py` exposes the variant behind
  `LEXMACHINA_GEOMETRY_VARIANT`. Off by default (incumbent byte-identical);
  `relevance_ordered` and `hydrate_then_cluster` are opt-in; an unknown value
  raises rather than being silently ignored.
- **Wiring**: `product/query/pipeline.py::_map_bundle` applies the variant after
  `build_map` and records `provenance.geometry_variant` and
  `provenance.map_component`.
- **Renderer precondition fix**: the variant marks un-hydrated context rows with
  unique **negative** `cluster_id`s. `product/static/query.html` previously set
  `ctx.fillStyle = COLORS[p.cluster_id]` for those rows, i.e. `undefined`, which
  Canvas ignores (leaving the previous row's colour). `colorFor(clusterId)` now
  paints them neutral grey (`UNCLUSTERED_COLOR = #9aa3ad`), and the legend text
  says so. `product/canvas_probe.js` gained `countFills()` to make the
  regression measurable (`fill_colors`, `fill_undefined`).

The variant is **not** defaulted on: the frozen geometry bar is 0/3, so nothing
is promoted into the served packet. A default run still records
`geometry_variant=incumbent`, `map_component=query-conditioned-tfidf-v45`.

Tests: `product/tests/test_qmap_geometry_variant.py` (13, including a tamper
check that re-hashes the vendored bytes against `PROVENANCE.json`) and
`product/tests/test_renderer_unclustered_context.py` (3, including a
discrimination control proving the pre-fix renderer left undefined fills).
