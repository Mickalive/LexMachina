## 1. Delta A — the defect, measured before the fix

`results/product/progressive_slice/39060279436_LIVE.json` (live run of this run id, before the fix):

```
"ok": false,
"budget": { … "points_moved_after_first_map": 7 }
```

Diagnosis (reproduced offline against the saved bundle, server booby-trapped): **0** coordinate changes, **7**
missing first-page rows, all of them listed in `provenance.adversarial_retrieval.replaced_row_ids` —
`bge_BGE_102_II_85`, `bstger_BG.2016.9`, `bstger_BG.2018.26`, `ge_gerichte_P_15662_2015`,
`ge_gerichte_P_19325_2022`, `ge_gerichte_AARP_355_2021`, `ge_gerichte_P_9357_2021`.

Cause, in the old code: admission policy `bounded_replace_tail_v1` held the row count constant by evicting the
weakest *unprotected* rows — "unprotected" meant "not cited and not already counter-labelled", i.e. exactly the
low-ranked rows on screen. The product's own
`test_apply_appends_unseen_rows_and_freezes_rendered_geometry` failed on it with a `KeyError` for an evicted
rendered id (4 `test_apply_*` failures were already red on the base commit).

## 2. Delta A — the fix

Challengers are now **appended while the map stays inside the MVP tractable window**
(`progressive.TARGET_MAX = 300`, the same constant `pipeline.MAX_RESULTS` uses) and are **skipped and recorded**
at the ceiling instead of a rendered row being removed:

* `admission_policy: "append_within_cap_v2"`, new provenance keys `map_row_ceiling`, `n_skipped_rows_by_ceiling`,
  `skipped_row_ids`, `rendered_rows_evicted` (always `0`), while `n_replaced_rows`/`replaced_row_ids` stay in the
  schema for readers — always `0`/`[]` under v2.
* Nothing about challenger ranking or the reranker changed; conventional rows keep their order, challengers rank
  after them.
* Labels are still **not** written by the retrieval pass (`heuristic_labels_surfaceable: false`, from 1381ed0):
  heuristics remain admission signals only.

## 3. Delta B — the answer is inspectable

* `renderAnswer()` now writes linked prose via `citedLink()`/`linkCitedIds()` (single regex pass, longest-id-first,
  `openCited()` → `showDetail()` + `status()`), plus an `#answerSources` chip row in `#answerMeta` so a model that
  *numbers* its citations is still fully reachable.
* All non-link prose goes through the existing `esc()`, so hostile prose is text, never markup.
* `product/verify_query_page.js` grew 9 assertions: reachability of every cited id, executing `openCited(...)`
  on both routes (inline link and source chip), and an escaping check (prose containing `<script>` must survive
  escaped, with the cited ids still linked).

**Measured:** page contract went **36 → 47 assertions** on the real live bundle
(`node product/verify_query_page.js results/product/progressive_slice/bundle_39060279436_LIVE_V2.json` → `PASS 47`), including
