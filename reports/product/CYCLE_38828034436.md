## 2. The fix — `product/query/adversarial_retrieval.py`

A second retrieval route, run **after** the provisional answer exists.

```
provisional answer ──► plan_adversarial_queries()  ──► fetch_adversarial_candidates()
  (its own legal         4 counter-directed            accepted ocl_adapter client +
   vocabulary, not        probes, DE+FR+IT               cache + transport + normalizer
   the question's)        adversarial.{exception,
                          contrary,minority,older_line}
                                   │
                                   ▼
                        apply_adversarial_pass()
                     id + court/docket dedupe vs the map
                     incremental projection join
                     evidence-gated labelling
```

Four properties worth auditing individually:

1. **Probes are answer-derived, not query-derived.** `answer_key_terms` extracts the answer's
   distinctive legal vocabulary; each probe anchors on those terms plus one intent's DE/FR/IT
   limitation vocabulary. A different answer yields different probes
   (`test_plan_changes_with_the_answer`). Attacking the *proposition*, not the question wording,
   is what makes the pass adversarial rather than a second copy of the first query.

2. **Channel independence is structural, not asserted.** The four channel strings are disjoint from
   the adapter's channel inventory (`search`, `search.language_filter`, `leading_case`,
   `citation.incoming`, `citation.outgoing`, `decision_lookup`) by construction, and
   `test_product_channels_are_disjoint_from_adapter_channels` asserts it. Everything the initial
   pass saw is dropped, by id **and** by court+docket identity — the same identity predicate
   `merge_duplicate_identities` uses, because a citation edge and a search hit can carry one
   decision under different ids.

3. **Classification is evidence-gated.** A row receives a counter label only when a verbatim
   sentence of its **own** decision text carries a limitation marker. The probe intent only orders
   the search; the evidence decides the label, and a row found by the exception probe whose text
   carries a dissent marker is labelled from the dissent
   (`test_marker_in_own_text_authorises_a_counter_label`). Unmarked survivors keep
   `counter_status="none"` — recall grows without inventing a legal label.

4. **The rendered map never moves.** Survivors join through the existing incremental seam
   (`progressive.map_model_from_bundle` + `qmap.build_map`); every already-rendered point is
   restored to its shipped coordinates (`test_apply_appends_unseen_rows_and_freezes_rendered_geometry`).
   If the projection cannot be reconstructed the pass **refuses** rather than place rows in a
   different space than the one the jurist is looking at.

`frontier/**` was not edited. The accepted adapter is *reused* (client, cache, transport,
normaliser) exactly as `pipeline.py` already reuses it.

Wiring: `pipeline.py::adversarial_retrieval_pass`, called from `enrich_query_bundle` after the
answer is ready, on by default, off for `fixture_generation`. Degradation is explicit and
verbatim — an upstream failure or an unplaceable projection contributes zero rows and is recorded
in `provenance.adversarial_retrieval.failures` / `skip_reason` / `error`. The pass never removes a
row the initial pass found and never raises out of `enrich_query_bundle`.
