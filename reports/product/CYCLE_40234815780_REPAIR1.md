### 1.2 Root cause, measured from committed bundle provenance (not asserted)

The old test pinned two things at once. Only the *first* one is the P0 contract:

1. **the shipped fixture path runs the content-rejection leg** — still true, still tested;
2. **the trilingual Graubünden letterhead decision is the fixture challenge row** — an incidental
   consequence of retrieval order, and this is what stopped holding.

`enrich_query_bundle` builds its fixture challenge from `work["decisions"][2]`, so whichever
decision sits at index 2 receives the fixture finding, passes the precision gate and is written
back as `counter_status="candidate-limiting"` with `counter_evidence_verified=True` and the cached
letterhead evidence. That row is then the one the rejection leg must downgrade.

Measured, both sides from the committed bundle bytes:

| | committed `20261025T204600Z/rent-default` | fresh `offline_slice.build_bundle` (this repair) |
|---|---|---|
| query cache keys | 899 | 938 |
| cache misses / degraded | 2 / `true` | 0 / `false` |
| `requests_by_stage` | `search 6, lang 3, leading 1, citations 3` | `search 6, lang 3` |
| `legal_concept` search variants | 2 (2 more missed) | 4 |
| candidates (pre-trim / served) | 165 / 165 | 199 / 180 (cap hit) |
| `decisions[2]` | `gr_gerichte_ERZ 2010 25` | `vd_gerichte_JL09.019144` |
| letterhead row `counter_status` | `candidate-limiting`, `verified=True` | `cited`, `verified=False` |
| letterhead row `counter_evidence` | trilingual header (4 lines) | `""` |
| rows explicitly `counter_evidence_unevidenced` | 1 | 1 |

The two `legal_concept` requests that *missed* the cache when the rejected cycle generated its
bundles are now present in the committed `results/product/query_cache` (the same cycle committed
46 cache files), so a fresh replay is no longer degraded, the pool grows past the 180-candidate cap
and the leading/citation stages never run. **The committed cache and the committed bundle are from
different cache states** — that is disclosed as a residual in §4, not silently absorbed.

fresh-build behavior", with the contract strengthened)

The repaired test asserts, on the bytes a fresh build actually produces:

  `content_filter.predicate_source_sha256` equals the pinned frozen-predicate source sha —
  unchanged assertions;
