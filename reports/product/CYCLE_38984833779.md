## 1. Obligation (5) — the RED recall leg, attacked concretely

### 1.1 What was actually wrong

The accepted cycle 38964140248 had widened `REMOTE_HEAD_RECALL_REMOTE_TOP`
5 → 15 and honestly recorded that this recalled only **2 of 5** frozen
direct-TF BJR authorities, with the audit concluding that `MAX_MOVED=3` was
"the true ceiling of this mechanism". This cycle first tested that conclusion
rather than accepting it, and it does not hold.

Offline replay of the frozen BJR question over this repository's own cache
(180 candidates, at the rerank seam *before* the `top_n` cap, so the whole
retrieval pool is visible):

```
every frozen authority present in the pool: all 5 — NONE is a retrieval miss
  bger_4A_219_2015  local rank   8   mixed-channel remote rank 12   local TF-IDF sim 0.0164
  bger_4A_259_2016  local rank  75   mixed-channel remote rank 13   local TF-IDF sim 0.0000
  bger_4A_626_2013  local rank   9   mixed-channel remote rank 14   local TF-IDF sim 0.0089
  bger_4A_603_2014  local rank  27   mixed-channel remote rank 18   local TF-IDF sim 0.0135
  bger_4A_62_2024   local rank  44   mixed-channel remote rank 47   local TF-IDF sim 0.0076
```

So retrieval was never the failure. The failure is in *how the window is
ranked*. The window sorted **all** candidates globally by
`retrieval_score_raw`, and the channels carry incompatible scales:

* `leading_case` rows are scored by **raw citation count** (6984 / 5710 / 4138 / …),
  so they occupy mixed-channel remote ranks 1–10 on this leg;
* lexical `search` rows score ~40–70.

Measured under the shipped window of 15: **6 of the 7 qualifying federal rows
were `leading_case`, and only 1 was `search`.** `leading_case` is a *global
citation-count leaderboard* — it answers "what is heavily cited in Swiss case
law", never "what answers this question". The window was therefore being spent
on rows that are not a per-question ranking at all.

### 1.2 The change

`product/query/relevance.py`: the window is now ranked **within the
query-answering channels** (`REMOTE_RECALL_ANSWER_CHANNELS = {search,
search.language_filter}`), named from the accepted adapter's own channel
vocabulary (`frontier/frontier-query-retrieval/ocl_adapter/normalize.py`).

Within the search channel alone the five frozen authorities rank **2 / 3 / 4 /
8 / 33** — the source index itself considers three of them top answers.

Nothing else changed. The window is never widened, the `MAX_MOVED=3` cap, the
federal-only rule, the `insert_at 8..10` splice, and the "never touch a row
already in the head" rule are all byte-unchanged. The mechanism still only moves
a row *to the generator*; citation validation and the adversarial pass
downstream remain free to reject it. **No frozen gate was touched** —
`product/reality_check.py`, `MEGA_CLUSTER_SHARE`, and both rubrics are
unmodified.

| corporate-criminal-liability | identical (3 rows moved) | identical |

The other three legs are **byte-identical**. The recall is strictly more

### 2.1 The renderer precondition the team flagged as BLOCKING

The team's `RENDERER_PRECONDITION.json` names a blocking precondition for
drop-in adoption: the variants emit **negative** `cluster_id` for un-hydrated
unclustered context, and `COLORS[(p.cluster_id??0)%COLORS.length]` truncates
toward zero in JavaScript, so `COLORS[-1]` is `undefined` and the canvas
silently keeps the previous `fillStyle`.

Fixed in the owning lane (`product/static/query.html`): `colorFor()` wraps the
index into range and paints negative ids in a **declared** neutral
(`#98a2ad`) rather than borrowing a group's hue, and the cluster legend uses it
too. Verified in Node against the **real** 187-point served bundle: 0 invalid
fillStyles, 25 shell points all `#98a2ad`, 7 distinct group colours. The
retired expression returns `undefined` for those same ids.

### 2.2 Two product-contract defects the integration exposed

Neither was resolved by weakening a test.

1. **Coordinate contract.** The adopted layout emits shell rows at
   `y = -1 + 0.05*jitter`, i.e. as low as **-1.025**, outside the product's
   `[-1,1]` contract that `screenPos` and three tests depend on. The team's
   output contract promises the range for `x` and leaves `y` unspecified, and
   the team writes no product code. Fixed in the **seam**
   (`_clamp_coord`), adapting the component to the product's contract without
   editing a byte of the team's source.
2. **Cluster-id accounting.** Two tests asserted
   `d["cluster_id"] in cluster_ids`, which the variant's deliberate
   unclustered-context rows break. Rewritten to the actual contract — every
   point must be in a declared group **or** be flagged `unclustered` with a
   negative id — which is strictly stronger than the old membership check: an
   unflagged orphan id still fails.

The historical claim-bundle replay (`product/replay_bundle.py`) is pinned to
the incumbent geometry, because it replays a **historical, claim-bearing
artifact** produced before this change. Regenerating the artifact to match a
new default is what AGENTS.md rule 6 forbids.
