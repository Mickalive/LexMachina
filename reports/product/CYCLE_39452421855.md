# Product Cycle 39452421855 — Query Map MVP Complete

## Summary

The query-map MVP is **functionally complete and ready for human product gate**. All core capabilities specified in `docs/product/QUERY_MAP_MVP.md` have been implemented, tested, and verified.

## Implemented Capabilities

### 1. OpenCaseLaw Retrieval + Caching ✅
- Broad multilingual retrieval (DE/FR/IT) via accepted `frontier-query-retrieval` adapter v2
- Query expansion with legal synonym lexicon (30+ term pairs across languages)
- Citation neighborhood expansion (incoming/outgoing)
- Leading cases channel
- Persistent file cache with request-key deduplication
- Configurable budget controls (max requests, RPS, page sizes)

### 2. Query Result Bundle (Integration Contract) ✅
Per ARCHITECTURE.md §24, all components converge on `query_result_bundle` v1.0:
- `query` + `query_variants` with full provenance
- `answer` with `prose`, `statements`, `cited_decision_ids`, `method`, `model`, `status`
- `decisions[]` with stable `decision_id`, `canonical_url`, `citation`, `court`, `language`, `decision_date`, `snippet`, `rank`, `score`, `cluster_id`, `x`, `y`, `is_outlier`, `counter_status`, `counter_evidence`, `counter_uncertainty`, `counter_evidence_verified`, `adversarial_channel`
- `clusters[]` with `cluster_id`, `label`, `size`, `member_ids`
- `relations[]` with typed citation edges from OpenCaseLaw `/citations` + shared-citation edges
- `provenance` with full timing, component versions, retrieval breakdown, relation channel state

### 3. Progressive Pipeline (Non-blocking UX) ✅
Per QUERY_MAP_MVP §9A, three-stage job architecture:
- **Phase 1** (`/api/query/start`): First OpenCaseLaw page → dedupe → rerank → map (target <1.5s local overhead)
- **Phase 2** (`/api/query/expand`): Background expansion to 100–300 decisions, map stable
- **Phase 3** (`/api/query/enrich`): Lazy evidence hydration → sourced generative answer → adversarial retrieval → counter classification
- Status polling via `/api/query/status`; resume via `/api/query/bundle?run_id=`

### 4. Sourced Generative Answer ✅
Via accepted `frontier-generative-audit` contract 2.2:
- Evidence pack built from top-ranked decisions
- Free-model generation (OpenCode CLI) with citation validation
- Explicit degraded fallback (extractive TF-IDF) when provider unavailable
- Answer-coverage contract fills missing statutory conditions from retrieved text
- Zero-citation contract surfaces covered/uncovered concepts honestly

### 5. Independent Adversarial Retrieval ✅
Per QUERY_MAP_MVP §6 and Master Prompt "Retrieval-first doctrine":
- Answer-conditioned probe planning (exception, contrary, minority, older_line)
- DE/FR/IT interleaved vocabulary (round-robin, no language truncation)
- Dedicated OpenCaseLaw search stage (`adversarial.<intent>` channels)
- Exclusion by decision_id AND court+docket identity
- Evidence-gated classification: verbatim sentence must carry marker + share topical term + not boilerplate/dismissal
- Appends unseen rows to map without moving rendered points (ceiling at 300)

### 6. Counter-Emission Repair + Anchor Classifier ✅
Two accepted Frontier components integrated per their INTEGRATION_CONTRACT:
- **frontier-counter-label-emission** (Outcome A): Promotes adversarial stage's gate-passed heuristic proposals into scored fields for classifier consumption
- **frontier-counter-anchor-classifier** (Outcome A): Confirm-or-abstain on scored rows under frozen RULES_LABEL.json (sha256 4457e971...); abstained rows stay visible as `abstained_unevidenced`; publishes support-among-issued, abstention count, yield side by side

### 7. Query-Specific Interactive Map ✅
Per QUERY_MAP_MVP §7 minimum semantics:
- Point = decision with x,y in [-1,1] normalized space
- Proximity = TF-IDF cosine similarity in query-conditioned space
- Clusters = KMeans on TF-IDF (deterministic, n_clusters adaptive)
- Outliers = furthest from cluster centroids (top 10%)
- Citation edges available on selection (typed from `/citations` + shared-citation)
- Counter-authorities visually discoverable (red ring = evidenced, amber dashed = unevidenced, cyan halo = adversarial discovery)
- Cluster labels = top TF-IDF terms (deterministic ordering: -round(mean,9), term)
- Map model fitted once; expansion projects new decisions into frozen space

### 8. UI (query.html) ✅
Single-page interface with:
- Question input + result count selector
- Sourced answer panel with clickable citations → decision detail
- Interactive Canvas map with pan/zoom/filter
- Counter-authority panel (status + evidence + rank)
- Adversarial discovery panel (provenance channels, not legal qualification)
- Cluster list with labels
- Relation channel disclosure (measured state, not guessed)
- Decision detail panel (snippet, cluster, relations, counter evidence, canonical URL)
- Language filter, search within results, fit/reset
- Map/list toggle via accepted `frontier-human-gate-harness` (same bundle, no re-retrieval)
- Owner-gate 4-question card (Master Prompt §12)
