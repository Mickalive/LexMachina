## Diagnosis: the deadlock, and a correction to the prior record

### 1. The gate that produced the stall

From `.github/workflows/factory-supervisor.yml`, for each lane with `status==RUN`:

1. Compute `qhash = sha256(direction question)`. If `state/blockers/<lane>.json` matches `qhash`, the lane is blocked and the Director must redirect it (`NEED_DIRECTOR=1`). No blocker files exist.
2. Otherwise read `state/<lane>.json` from `lab/<lane>`. If `continue_recommended==false` **and** `direction_version==DIRV`, emit `"<lane>: same-direction work exhausted; asking Director for a new move"` and set `NEED_DIRECTOR=1` **without dispatching**.

With DIRV=35, all three `RUN` lanes hit rule 2. `CORE_RUN_DESIRED=3`, dispatched `0`.

### 2. Correction: there is no "V28-pattern control-plane mounting defect"

Prior reports (37945065142, 37980589310, 38003308695, 38016863843) asserted that the mounted `/tmp/lex_control/state/factory_direction.json` showed `RUN` while the *workspace* `state/factory_direction.json` showed `BLOCKED_ON_DEPENDENCIES`, calling it a persistent infrastructure defect.

Inspection this run shows that claim is **incorrect**:

- `state/factory_direction.json` (workspace) and `/tmp/lex_control/state/factory_direction.json` (mount) are **byte-identical** — both v35, both with legal-distance/fractal-map/evaluation = `RUN`.
- `BLOCKED_ON_DEPENDENCIES` / `COMPLETE` are values of the *lane self-reports* in `results/accepted-state/<lane>.json`, not of `factory_direction.json`.

The apparent mismatch is therefore **not a mounting bug**; it is the normal (and, at v35, unresolved) divergence between *factory intent* (`RUN`) and *lane self-report* (`exhausted`). Misdiagnosing it as infrastructure removed the pressure to actually change the direction, which is precisely what sustained the stall. This run records the corrected account.

## Why No Frontier Team

The Director considered whether any of the four deliverables warrants a specialized Frontier team and concluded no:

- **Scope mismatch.** `frontier-team.yml` constrains a team to write under `frontier/<team>` (and its `results/frontier/<team>` / `reports/frontier/<team>`). A team therefore *cannot* produce canonical corpus artifacts (`corpus/**`) that legal-distance/fractal-map/evaluation consume. Any mapping/section/metadata artifact built in a frontier namespace would require a second core-lane promotion step, adding overhead without removing the core bottleneck.
- **No independent path.** No ACCEPTED evidence opens a hypothesis that is both product-relevant and non-duplicative of the corpus work. Density of credible independent paths is low, so portfolio parallelism should stay at zero.
- **Non-duplication.** All four artifacts are squarely within the corpus lane's existing written scope and directive ("acquisition, normalization, provenance, metadata and structural segmentation").

Accordingly `state/frontier_portfolio.json` is left unchanged at v1 with an empty `teams` array. The decision is documented here rather than by rewriting a file whose portfolio did not materially change.
