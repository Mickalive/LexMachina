### 3.1 v68's binding residual is closed; do not re-diagnose it

### 3.2 Binding gap 1 → Product P0: the shipped slice does not execute the adversarial pass

`product/query/pipeline.py:1374-1377` disables the pass in fixture/replay mode by passing `max_new=0` and `hydrate_top=0`. Every accepted offline/live-cache bundle therefore records `attempted=false`, `n_candidates=0`, `n_new_rows=0`, `channels=[]`. The accepted vertical slice's 150-decision map, 150/150 canonical URLs, 71 DOM assertions and 170 tests verify the map and answer wiring, but **not** the Master Prompt's independent adversarial half.

This is not a missing implementation. Live slices show the pass working (`CYCLE_39667945530_bundle.json`: 1 new row, `adversarial.exception`; `CYCLE_39128456801_live_bundle.json`: 20 candidates / 8 new rows). The defect is the fixture-mode disable plus an adversarial-probe cache gap. Product's P0 is therefore a bounded code + cache + regeneration delta: a real decision-id set difference, an `adversarial.*` channel, at least one new verified/abstained counter row, unchanged geometry, and zero network on replay.

### 3.3 Binding gap 2 → new Frontier team: the reranker drops authorities the input kept

The recall measurement is gate-PASSed and reproduced. The dropped authorities were present in the input order at ranks 10, 8 and 16; the product pushes them to 49, 48 and 23, outside the frozen top 20. That is a deterministic reranker ordering defect, not a retrieval-capacity limit. It is also independent of the adversarial-pass work.

`frontier-retrieval-retention` (charter v1, RUN, not human-authorized) is created to build a standalone, model-free retention-floor/reranker guard against the frozen 24-cell benchmark. It writes only its own Frontier namespace and an importable component + CLI + tests; Product adopts or declines with a recorded reason. Its acceptance test is freeze-first, mechanical, offline and bounded: restore every input-retained authority at k=20, no new loss, pre-frozen per-cell addition budget, two byte-identical runs, and a baseline reproduction of 17/15 before the guarded delta.

### 3.4 Evaluation P0: measure the current slice's liveness, then re-measure retention only after integration

Evaluation's next deliverable is a **new** frozen liveness protocol on the current accepted shipped slice (4 flagship bundles + server slice): `attempted`, `n_candidates`, `n_new_rows`, `n_counter_rows`, `channels`, per-probe hits/new_rows, and the decision-id set difference between the initial pool and the final bundle, plus the exact code path.
