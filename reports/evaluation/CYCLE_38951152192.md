## 2. Finding F7: the lane suite reds a bare checkout for a missing optional dependency

`evaluation/lane_suite.py` advertises a **stdlib-only** entry point for auditors ("No Product code is imported and no network call is made"). Its final section shells out to pytest — which is *not* stdlib — and when pytest was absent `run_pytest` recorded a **FAIL** (`"pytest available", False`), so the whole suite exited 1 at **41/42** with the self-contradictory detail *"(this is a dependency gap, not a benchmark failure)"*.

Reproduced in this container before installing pytest:

```
cached replay vs live latency separation:
  [PASS] ...
pytest pass over the active lane test files:
  [FAIL] pytest available  pytest is not installed; ...
lane suite: FAIL (41/42 checks, 0.565s)
```

Why this is lane-business, not trivia: the suite is the artifact an auditor or validator runs first in a fresh checkout. A red verdict that measures the *environment* rather than the *product* is a false red — it either fails an otherwise-green validation or teaches readers to discount red. The 20 falsifiable stdlib gate families (digests, record integrity, byte-identical re-score, replay/live separation, falsification matrix) are the authoritative content; pytest is a convenience runner over the same gates.

* `evaluation/lane_suite.py` — `_Log.skip()` as a first-class third state (`passed: None`, `skipped: True`, `[SKIP]` marker); `failed` now excludes skips. `run_pytest` records a **SKIP** when pytest is absent and is unchanged otherwise: **a present-but-red pytest run still fails**.

* `tests/evaluation/test_lane_suite.py` (+3 functions): bare-environment end-to-end via `python -S` (site-packages disabled, stdlib intact — a faithful missing-pytest simulation asserting exit 0, `overall_pass`, `n_failed == 0`, `n_skipped == 1`, and that the stdlib checks still ran); `--skip-pytest` emits no pytest check at all; a monkeypatched red pytest subprocess still records a failure (the skip is not an amnesty).
