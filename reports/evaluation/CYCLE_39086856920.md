### F3 (MED) — check 21's state-source scan was defeated by dict ordering

**The defect, reproduced before the fix.** The state scope was serialized with
`json.dumps(state_scope, ensure_ascii=False)` — **one physical line**, so `_is_retraction_context`'s
documented "anchoring the left edge to the line start" defence could never engage, and the ±260
character window was the only barrier. This producer's measurement of the injected defect shape:

| injected bare `NO_NEW_PACKET` + "trigger does not fire" assertion | negatives surviving (pre-fix) |
| --- | --- |
| at the **HEAD** of the state scope | **0 — silently excused** |
| at the **TAIL** of the state scope | **0 — silently excused** |
| sharing a line with a retraction cue | **0 — silently excused** |

> **Provenance note, stated rather than smoothed over.** The audit reported 3 surviving negatives at
> TAIL. This cycle measures **0 at both HEAD and TAIL** on its own injected shape. The two readings
> agree on what matters — the assertion was **excused, not caught** — and the difference is in the
> injected text, which carries `"direction_item_1_trigger_fires": False` on the same line; the
> pre-fix marker `\bfalse\b` matched that bare JSON boolean too. Both numbers are preserved.

That is the real root cause and the audit only reached it by inference: **`false` as a retraction
marker matches a machine boolean.** Any sibling field carrying `false` excused a claim within
260 characters of it. This is not hypothetical — `state/evaluation.json` is dense with boolean
fields, and the historical defect lived in exactly this source.

**The fix, two halves.**
1. The state scope is scanned **one top-level key at a time**, with `indent=2`, and bare JSON
   literals `true|false|null` are masked in machine sources (a quoted English "false" inside a
   JSON *string* still counts as a retraction cue). The scan is now **independent of dict
   ordering**: a retraction cue in a sibling field can never excuse a claim in another.
2. The retraction window is scoped to the claim's **own sentence plus one sentence either side**
   on whitespace-collapsed text, instead of a raw ±260-character window anchored at a line start
   that cannot exist for JSON.

| control | pre-fix | post-fix |
| --- | --- | --- |
| bare negative claim at HEAD of state scope | 0 surviving | **3 caught** |
| bare negative claim at TAIL of state scope | 0 surviving | **3 caught** |
| live assertion sharing a line with a retraction cue | 0 surviving | **1 caught** |
| sibling boolean `false` next to a claim | excused | **caught** |
| the real `CYCLE_39082753086.md` report | — | **0 false positives** |
| the real state scope | — | **0 false positives** |
| preserved retraction prose (5 shapes) | excused | **still excused** |

**The rule is strictly stronger, not a trade.** The new window is a subset of the old one and the
marker set is unchanged apart from the machine-literal mask applied only to JSON, so every claim
the new rule catches the old rule caught too. No claim that used to be caught can now be excused;
the only movement is false-positive → catch, which is the direction the audit asked for.

Pinned by `test_check21_state_scan_is_order_independent_at_head_and_tail`,
`test_check21_state_scan_catches_an_assertion_sharing_a_line_with_a_retraction_cue` and
`test_check21_sibling_boolean_false_never_excuses_a_claim`. The four pre-existing check-21 controls
still hold unchanged.
