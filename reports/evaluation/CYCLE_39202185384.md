## 7. Freeze discipline, including the part that is weaker than it should be

The hypothesis was committed at `95499f16` before the formal execution. All **21 pinned digests**
(12 served bytes, 3 product modules, 6 lane-frozen files) re-hashed **21/21 before and after** the run,
with `pins_unchanged_during_run: true`.

**Two disclosed weakenings, stated rather than concealed:**

1. **Pre-freeze peek on L3.** While locating the served bytes, `verify_file()` was run once per bundle
   interactively (after installing numpy/scipy/scikit-learn, which were absent). It already showed the
   finding firing. So L3's "frozen before execution" property is genuinely weakened. This is recorded
   verbatim in the hypothesis's `pre_freeze_disclosure`. The formal run is still falsifiable: a stale or
   reverted admission module, a moved input digest, a lost finding, or a vacuous always-on finding each
   produce a non-zero exit. The peek did not touch L1, L2 or L4.
2. **Debug iterations.** The instrument was developed against scratch output directories; the first
   successful scratch run already exhibited the `fr-bail-entreten` vacuity. No claim here rests on the
   scratch runs — the committed record is the formal run, re-executed after the final code change.

**Post-refactor reproducibility.** `classify_l3` was factored out after the first formal run so tests
drive the same code rather than a copy. The formal run was **re-executed** afterwards.

**Reproduction from the committed tree**, machine-checked at
`results/evaluation/product_served_bundle_falsification/39202185384_reproduction_check.json`: a fresh
execution of the committed instrument against the accepted mount reproduces the committed record on
**every claim-bearing leaf**. Recursive leaf-by-leaf diff: **4 differing leaves, 0 excluding
wall-clock** — `generated_at`, `wall_seconds`, and the two `recompute_seconds` durations. Durations are
measurements *of time* and are explicitly not claimed to be deterministic.

> The checker that produced this number initially **defined its recursive walker and never called it**,
> and so reported "0 differing leaves" — a false clean. The call is now made and the checker asserts
> `differing` is non-empty, so it fails loudly if it ever stops running again. Recorded here because the
> factory's binding defect class is exactly "a published claim does not reproduce from the committed
> tree", and a checker that silently checks nothing is the same failure wearing a different hat.
