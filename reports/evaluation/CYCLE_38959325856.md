### 1.2 Root cause, reproduced this cycle

`core-lane.yml:55-60` runs, under `set -euo pipefail`:

```bash
TEAM="cycle/core/${LANE}/${REPAIR_FROM}/team"
AUDIT="cycle/core/${LANE}/${REPAIR_FROM}/audit"
```

**Reproduced locally this cycle:** a single `git fetch` carrying one existing refspec and
one missing refspec **exits 128 and updates neither ref**:

```
$ git fetch origin 'refs/heads/cycle/core/evaluation/38953399026/team:…' \
                    'refs/heads/cycle/core/evaluation/38953399026/audit:…'
fatal: couldn't find remote ref refs/heads/cycle/core/evaluation/38953399026/audit
FETCH_EXIT=128
$ git rev-parse --verify refs/remotes/origin/probe/team
fatal: Needed a single revision
```

Consequence: **a repair dispatch for a cycle that never produced an audit branch cannot
start.** The step aborts at line 1, `git switch -C repair-base` never runs, the agent is
never invoked, and the `if: always()` persist step then re-pushes whatever HEAD the
`actions/checkout` left behind. This is a chicken-and-egg trap: a cycle that dies before
audit can never be repaired, because repairing it requires the audit branch it never made.
`38953399026` is exactly such a cycle, so a `repair_from_run_id=38953399026` dispatch was
guaranteed to be a no-op — which is precisely the observed zero-delta state.

`.github/**` is control-plane scope and is **not edited from this lane**. Intended fix for
the control-plane maintainer: fetch the two refs in separate commands with the audit ref
tolerated as absent (`git fetch … "$TEAM:…" || true` is not enough — split the fetch, or
`git fetch origin "$TEAM:…"` then `git fetch origin "$AUDIT:…" || true`), and only mount
`/tmp/lex_prior_audit` when the audit ref actually resolved.

## 2. Why a new benchmark, and the reuse boundary

The accepted audit of 38951152192 (`results/audit/evaluation/CYCLE_38951152192_GATE.json`,

**What was deliberately NOT done.** The accepted Frontier rubric

already returned **FAIL, 0/3 bundles** on the served packet, with the French mega-cluster
at 0.7696 against a frozen bar of 0.60. Restating those eleven criteria, re-running that
harness, or re-deriving its verdict here would duplicate accepted evidence and churn a
frozen rubric. The `not_in_scope` block in the frozen spec says so in machine-readable
form.

**What is new.** The map *contract* layer, which no gate in this repository tested:

| gate | Master-Prompt semantic it enforces |
|---|---|

## 3. Freeze discipline

`evaluation/map_gate/build_frozen_spec.py` **refuses to overwrite** an existing spec.
`evaluation/map_gate/frozen.py` pins `FROZEN_SHA256` and re-verifies it before every
execution and inside the lane suite; the loader additionally rejects a reordered
inventory, a dropped gate, a moved bar and an emptied lexicon. `FREEZE_RECORD.json`
carries the same digest, the hypothesis, the success rule, and the disclosure below.

**Ordering.** Spec written 20:07:34Z; the claim-bearing record produced afterwards.
Verified by the suite (`map freeze precedes execution frozen_at=2026-10-16T20:07:34Z
inputs=31`).

**Input selection: none.** The inventory is the *complete* set of accepted product
bundles matching a mechanical rule declared in the spec (≥50 decisions, ≥2 clusters,
finite `x`/`y` on every row, ascending path order). **31 bundles**, each with its sha256
pinned. No bundle was picked, dropped or reordered after results were seen, and the
spec is the input set — `test_frozen_inventory_is_the_whole_in_scope_population_not_a_selection`
fails if it ever shrinks below 25.

**Pre-freeze disclosure (verbatim intent, also in `FREEZE_RECORD.json`).** A *feasibility
reconnaissance* preceded the freeze and is excluded from the claim-bearing verdict: three
served-packet bundles and the Frontier `RULES_GEOMETRY` input list were scanned for cluster
sizes, member-list lengths, distinct rounded coordinates, origin pile-ups, `counter_status`
counts, `is_outlier` counts and label texts, to decide *whether* a map-contract benchmark
was feasible and *which* Master-Prompt properties to gate. **No bar was chosen to obtain a
verdict**, and the bars are derived from product semantics rather than from any observed
number:

* `unreachable_count == 0` and `size_mismatch_count == 0` are exact contract requirements;
* `max_coincident_cell_share = 0.01` is a near-zero "you must be able to pick it apart" bar
  — with the smallest in-scope bundle (n=100) it still permits one coincident pair, with the
  largest (n=287) at most two;
* `label_language_min_share = 0.8` is a majority-of-labels bar, so one unusual label cannot
  fail a bundle;
* `MAP::counter_authority_selectable` is the conjunction of two already-frozen primitives
  applied to the counter subset, so it introduces **no new threshold**.

The reconnaissance did reveal that the problems exist — that is precisely why the gates were
frozen to be decisive rather than lenient. What counts is the verdict the frozen spec
produces over the whole inventory, and it is reported whatever it says.

**One code change landed between two pre-record probe runs and is disclosed here:** the
tokenizer gained the same `<mark>…</mark>` stripping the reality and retrieval benchmarks
already have, so a markup wrapper can never become a token. Verified to change **zero**
verdicts and **zero** query-language inferences (0 diffs across all 31 bundles and all
five gates). The frozen spec digest was unaffected; the claim-bearing record was produced
after the change.

**The label-language gate is deliberately conservative, and under-reports.** A label is
convicted only when *every* lexicon-attributed token belongs to exactly one language and
that language is not the query's. Tokens attributed to several languages (`in` is German and
Italian; `la`/`il`/`non`/`ne` are French and Italian) and content words absent from the
lexicon are ignored. Query language is inferred by the same frozen rule — argmax over
exclusive tokens, ties and all-zero votes yield `unknown`, and the gate is then
`not_measurable` with a reason and never counts as a pass. Consequence: the Italian query
bundles whose labels read `indennità, assicurato, decisione, scheda` are **not** convicted,
because those are content words. A benchmark that guessed would be worse than one that
under-reports.

### 4.1 F9 — cluster membership is truncated (23/31)

* `unreachable_count > 0` on 23 bundles, `size_mismatch_count > 0` on 23 bundles.
  Verified as a **set relation**, not by matching counts: intersection = 23,
  `unreachable \ size` = 0, `size \ unreachable` = 0, and the union equals the gate's own
  failure set exactly. So all three sets are the same 23 bundles.
* Aggregate: **1799 of 5313** cluster-assigned decisions (33.86%) are unreachable.
* Signature: `size` caps at 167 while `member_ids` stops at 50 on the FR served packet
  (also 81/50 and 78/50 on DE, 99/50 on IT). `member_ids` never names a decision absent
  from the bundle on any of the 31 artifacts, so this is a truncation, not a dangling
  reference.
* The 8 bundles that pass are exactly those whose clusters never exceed the cap:
  `it-responsabilita-medica` (38799024807), `bundle_it`, `bundle_it_repaired`,
  `bundle_fixture_kundigung_100`, the three `offline_machinery_rehearsal` fixtures and
  `bundle_CYCLE_38665681083_fixture`.

**Why this matters to the product.** Drill-down, cluster-scoped relation edges and
cluster-level counter sweeps are all truncated at the same place. This is the concrete
mechanism behind the divergence factory-direction recorded earlier this week, where
`gate_admissibility.py:292` read `len(member_ids)` and reported a French share of 0.3731
while the true `size`-based share was 0.557 — **both numbers are correct for the field they
read**, and the gap between them is this defect.

### 4.2 F10 — points are not distinguishable (31/31)

* Worst-cell share ranges 4.76% → 44.60% (median 14.29%) against a 1% bar.
* Rows sharing a cell with at least one other row: 11.11% → 75.33% (median 28.91%).
* **24 of 31 bundles** place their worst cell at exactly `(0.0, 0.0)`.
* Worst artifact: `clickable_slice/bundle_live_enriched_CYCLE_38740365477.json` — cell
  `(0.0, 0.0)` holds **128 of 287** decisions and **185 of 287 rows** are not individually
  addressable.

**Honest limitation.** The gate reads only the shipped rounded coordinates. It cannot
distinguish "the projection genuinely placed many decisions at the origin" from "the
serializer wrote a default for rows that never got a coordinate" — the coordinates are
present and numeric on every row in all 31 bundles, so `x`/`y` is never missing. Isolating
which of the two it is is the named next cycle (§6).

## 5. Non-vacuity, and how to re-run everything

A falsifying benchmark is only worth its FAIL if it can also pass. Both directions are
pinned:

* **Every gate can fail.** Five breaking fixtures, one per gate, wired into the lane suite's
  falsification matrix (`_broken_map_fixtures`). The matrix now covers **25 families**
  (was 20) and all 25 break.
* **Every gate can pass.** `check_map_is_satisfiable` builds a well-formed 200-row bundle
  and asserts it clears all five gates with **zero** `not_measurable`; the same is pinned by
  `test_clean_bundle_passes_every_gate_so_a_fail_is_a_real_finding`.
* **The bars are bars, not prohibitions.** `test_points_gate_tolerates_one_coincident_pair_exactly_at_the_frozen_bar`
  proves 2/200 = 0.01 passes and 3/200 = 0.015 fails;
  `test_label_gate_bar_boundary_is_eight_clusters_not_a_unanimity_rule` proves 1 bad label
  out of 8 passes and out of 3 fails.
* **The record cannot be typed.** `--rescore` re-derives every verdict from the frozen spec
  plus the accepted mount; the suite runs it and requires an exact summary match.
* **A tampered spec cannot be used.** Eight loader-rejection tests cover a weakened bar, a
  dropped gate, a reordered inventory, a stripped sha256, a changed schema and an emptied
  lexicon.

Commands:

```bash

    --product-root /tmp/lex_accepted/product --run-id <id> --out <record>.json

    results/evaluation/map_benchmark/38959325856.json
```

## 8. Recommendation

**HAND OFF TO PRODUCT with three named, located defects.** The map is the product. The
three findings are cheap to act on and are not judgement calls:

1. **`clusters[].member_ids` truncation** — enumerate the whole membership or ship a

   membership list, which directly undercuts the product's adversarial requirement.
