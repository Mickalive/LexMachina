## 2. Defects found — all three are in the harness, none is in the product

### D10 (MAJOR) — the load-bearing metric could not answer the question it was asked

`b1_adversarial_channel_rows` asks whether a counter row carries a channel the *initial broad
retrieval* never used, where the "initial" inventory is
`populations.initial_channel_set()` = the keys of `provenance.retrieval.candidate_channels`
(unioned with `dedupe.candidates_by_channel` and `retrieval_first_page.candidate_channels`).

That object is the channel union of the **final persisted pool**. A build that *did* run an
adversarial retrieval round would add that round's channel to exactly that object, so every
counter row would still satisfy `channels ⊆ initial_channel_set`, b1 would still be 0, and the
harness would report `FAIL` for a genuinely retrieval-independent pass.

The published number `0 of 8` is therefore a statement about the *pool's declared channel
vocabulary*, not about whether an adversarial retrieval occurred. **This does not invalidate the
verdict** — the bias runs against the product, so the instrument can only under-claim — but the
published claim was phrased more broadly than the instrument supported.

The artifacts already carried the missing evidence and the harness never read it:

```
B1/B2  provenance.retrieval.remote.stages      = ['search','lang','leading','citations']
       provenance.request_summary.requests_by_stage = {'search': 1}
B3     provenance.retrieval.remote.stages      = ['search','lang','leading','citations']
       provenance.request_summary.requests_by_stage = {citations,decision,lang,leading,search,structure}
legs   no provenance at all
```

**New module `adversarial_paths.py`** reads the stage inventory, the per-stage request log and
the unaccounted-channel set, and reports `NO_ADVERSARIAL_RETRIEVAL_STAGE` for all 7 artifacts
with `channel_vocabulary_closed = true` everywhere. A retrieval round that does not exist cannot
appear in a stage inventory; a round that did would have to.

### D12 (LATENT) — a missing language marker was scored as a minority language

`populations.modal_language()` deliberately refuses to let `"?"` win a consensus band ("that
records a missing value, not a language"). `metric_g_minority_reach()` then computed
`non_lang = language != consensus_language`, which is **true** for `"?"`. Any counter row whose
language was simply unrecorded therefore counted toward `minority_reach_share` — and metric (g)
is the one metric that **PASSes on all three frozen bundles**. Fixed with an explicit
`populations.language_known()` predicate; unknown rows are now counted in a new
`n_counter_rows_with_unknown_language` field and excluded from the share.

The defect could flip the verdict (a bundle whose counter rows are all unlabelled scored
`PASS 1.0`); it is pinned by `test_unknown_language_can_flip_minority_reach_from_pass_to_fail`,
which reproduces the pre-D12 formula inline and shows `1.0 → 0.0, PASS → FAIL`, while confirming
a genuinely older FR row still PASSes. **No frozen artifact is affected** — every counter row in
B1/B2/B3 carries a real `de`/`fr`/`it` value — which is why the report still hashes to
`b15ea198…`.

### D13/D14/D15 (LATENT, in the new code, caught by running it before shipping it)

Three defects in the D10/D11 implementation itself, found by executing the numbers rather than
reading them:

* **D13** — `_strip_prose()` collapsed a docstring to one space, shifting every subsequent line
  number, so the "code-only" copy was no longer evidence for the source it cited. It mislabelled
  `AdversarialPass` as not pool-internal. Fixed to blank characters while preserving newlines;
  pinned by `test_prose_stripping_preserves_line_numbering`.
* **D14** — `FETCH_CALL_TOKENS` contained `.search(`, which matched `re.search(` and credited
  `AdversarialPass` with retrieval capability. Replaced with regexes carrying `(?<!re)` /
  `(?<!str)` / `(?<!dict)` lookbehinds; pinned by `test_regex_search_is_not_mistaken_for_a_
  retrieval_call`.
* **D15** — `SCAN_ROOTS` overlaps (`product/query` sits inside `product`), so every mechanism was
  counted twice. De-duplicated by `realpath`; pinned by `test_overlapping_scan_roots_do_not_
  double_count`. Test-symbols are excluded from the shipped inventory but **listed**, so the
  exclusion is auditable rather than silent.

## 3. Non-vacuity of the new evidence channel

A negative finding is only evidence if the instrument would have fired.
`adversarial_paths.self_test()` injects two synthetic adversarial retrievals into a deep copy of
B1 and re-runs the detector. Both flip; gate `PASS`.

| case | injected | stage evidence | frozen b1 after injection |
|---|---|---|---|
| `stage_only` | declared + logged stage `adversarial.negation_search`, rows untouched | fires | — |
| `channel_and_stage` | stage declared + logged **and** the channel absorbed into the pool union, counter rows re-channelled | fires | **0** |

The second row is the whole point: with the adversarial channel absorbed into the pool union,
`b1` still reads **0** and `channel_vocabulary_closed` is still **true**. That is the exact
situation D10 says metric (b) cannot see, and it is now demonstrated rather than argued.

### Residual blind spot — declared, not hidden

Stage evidence still cannot see an adversarial round that is neither declared in the stage
inventory, nor logged, nor introduces any new channel. That residual is recorded in the artifact
under `stage_evidence_self_test.residual_blind_spot`, and it is covered by the other channel:
`mechanism_inventory` measures whether *any* accepted mechanism is even capable of a fetch. The
two are complementary; neither is load-bearing alone.
