## 3. Defect A — unbounded operational resume loop

1. The charter is terminal and audited PASS; there is nothing left to execute.
2. The portfolio entry is still `status: "RUN"`, so the Frontier finalizer's
   `CURRENT_STATUS != RUN` guard does not fire and it dispatches another resume.
3. A resume onto a finished charter correctly makes no change.
4. `LEX_REQUIRE_DELTA=1` turns that success into an **error**:

   `.github/scripts/run-ox-with-retry.sh:216`
   ```bash
   if [[ "$cur" == "$START_HEAD" && -z "$delta" ]]; then echo "::error::LEX_ZERO_DELTA_REPAIR"; exit 67; fi
   ```
   `.github/workflows/frontier-team.yml:145`
   ```bash
   echo "::error::Frontier producer returned success with zero durable delta"
   ```
5. The failing `team` job makes the finalizer dispatch yet another resume.

The loop is unbounded while the portfolio entry stays `RUN`. **This team cannot
break it**: the `Enforce team scope` step permits writes only under
`frontier/<team_id>/**`, `tests/…`, `results/…`, `reports/…`, `data/…` and
`state/frontier/<team_id>.json`. `state/frontier_portfolio.json` is excluded, and
charter acceptance test (9) forbids it independently. Moving the team off `RUN`
is the director's write, exactly as the charter's own stop rule says.

## 4. Defect B — the team's own code package is outside its enforced write scope

The scope guard's pattern is `frontier/$TEAM/*` with `TEAM=frontier-query-concept-recall`,
i.e. it matches **`frontier/frontier-query-concept-recall/*`**. A Python package
cannot be named with hyphens, so the importable package necessarily lives at
**`frontier/frontier_query_concept_recall/`**, which does **not** match.

Empirically confirmed: run **39179862363** failed at `Enforce team scope`
(exit 4) after editing the package. The consequence is structural:

> **No Frontier team whose id contains hyphens can ever edit a Python package it
> ships.** Every attempt fails the guard.

**Resolution taken this cycle:** the accepted package — accepted at
`lab/frontier/frontier-query-concept-recall` = `bd1b4d73`, audit `PASS` — is left
**byte-untouched**, and every new artefact lands in the in-scope directory
`frontier/frontier-query-concept-recall/`. The defect is reported, not worked
around silently.

Remaining options for the control plane:

- widen the scope pattern to also admit `frontier/<team_id_with_underscores>/`, or
- relocate the package to `frontier/<team_id>/frontier_query_concept_recall/` —
  the import name is preserved and the path is in scope (requires re-audit).

## 5. Defect C — offline replay against a fresh `--out` fabricates a gate regression

Charter acceptance test (3) names `--bundle <path> --out <dir>`. The accepted
harness roots its A1 cache only at `<out>/cache`, so with a **fresh** `<dir>`
and `--offline` no cached envelope is found for any A1 query, each is treated
as an errored search, and the run reports a gate regression that is not real:

```
--out <fresh>      --offline  ->  regressed_gates: ["transport::all_queries_ok"]
--out <committed>  --offline  ->  regressed_gates: []
```

A spurious gate failure is exactly the thing that must not be papered over, so
it is fixed — **without touching the accepted package**:

`frontier/frontier-query-concept-recall/run_harness.py` is an offline-safe entry
point that seeds a read-only scratch cache copy and **aborts loudly (exit 2)**
when no envelope is visible anywhere, instead of degrading silently. Verified:
it produces `regressed_gates: []` on a fresh `--out`.

```bash
PYTHONPATH=frontier python frontier/frontier-query-concept-recall/run_harness.py \
    --out /tmp/scratch --offline
```
