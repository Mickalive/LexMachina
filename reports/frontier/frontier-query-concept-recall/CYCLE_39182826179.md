## Defects found, and what was done about each

### F — the charter's own acceptance test (3) invocation was not runnable *(repaired in scope)*

Acceptance test (3) names exactly:

```
python -m frontier_query_concept_recall.cli --bundle <path> --out <dir>
```

`load_bundles` returns **only** the supplied paths when `--bundle` is given
(`cli.py:1005-1015`), but the A3 shuffled non-vacuity control unconditionally
indexes a *sibling* served question (`cli.py:416-418`). So the one-bundle form
of the charter's own named invocation dies with a raw:

```
KeyError: 'fr-bail-entretien'
```

before it can emit a record. Reproduced offline, zero network. This is an
engineering defect, not a result.

**Repair** — `frontier/frontier-query-concept-recall/cli_entry.py`. The served
question *set* is fixed by the charter, not by the caller; `--bundle` selects
which are *named*. The entry point completes any missing served question from
the RULES-pinned, sha256-verified, read-only accepted bundle bytes, discloses
exactly what it completed under `entry_point`, and aborts with exit 2 and an
actionable message rather than crashing if a sibling cannot be resolved. It
never fabricates or degrades a control.

It also repairs defect C (offline replay against a fresh `--out` fabricating a
`transport::all_queries_ok` regression) and makes acceptance test (3)'s literal
field names — `rows_per_concept`, `under_covered`, per-language authority
recall — resolve as **aliases onto the same objects** the accepted artifact
names `concept_row_counts` / `concepts_with_zero_rows` / `recall`. Purely
additive; nothing is renamed, removed or recomputed.

**Measured neutrality proven**: the completed served set produces a claim-bearing
body identical to the full run (pinned by a test).
