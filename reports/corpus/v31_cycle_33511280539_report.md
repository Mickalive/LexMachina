## Key Finding: bge_/bger_ Naming Mismatch (Glob Bug)

**Root Cause**: Two separate ingestion scripts produce different file naming conventions:
- `ingest_bge_parquet.py` creates `bge_YYYY.jsonl` files (21k BGE subset, from `bge.parquet`)
- `reproduce_full_corpus.py` creates `bger_YYYY.jsonl` files (174k full BGer corpus, from `bger.parquet`)

The `.gitignore` ignores `bger_[0-9][0-9][0-9][0-9].jsonl` (the canonical output) but NOT `bge_[0-9][0-9][0-9][0-9].jsonl` (the BGE subset). In a fresh workspace:
1. `bge_*.jsonl` files are present (committed to git, 21k records)
2. `bger_*.jsonl` files are absent (gitignored, 0 records until reproduce runs)
3. Tests look for `bger_*.jsonl` → **FAIL** with 0 year files found

**Resolution**: Running `reproduce_full_corpus.py --force-download` regenerates the `bger_*.jsonl` files, which the tests then find. The pipeline is self-consistent after reproduction but requires the parquet download step.

**Recommendation**: Update `.gitignore` to also ignore `bge_[0-9][0-9][0-9][0-9].jsonl` for consistency, or consolidate the two ingestion scripts to produce files with the same prefix.
