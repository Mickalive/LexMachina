## Root Cause

The `build_product_integration.py` script used `load_metadata()` which read only the baseline `metadata.json` (lacking the `branch` field). The corpus files at `/tmp/lex_accepted/corpus/corpus/normalization/canonical/` containing branch labels were not accessed during product integration artifact generation, even though the hierarchical map builder (`hierarchical_map_builder.py`) correctly used them via its `load_metadata_with_branch()` function.

---

## Fix Applied

### 1. Modified `build_product_integration.py`

Added the `load_metadata_with_branch()` function (copied from `hierarchical_map_builder.py`) that:
- Loads baseline metadata from `BASELINE_DIR/metadata.json`
- Reads corpus files (`bger_20*.jsonl`) from `/tmp/lex_accepted/corpus/corpus/normalization/canonical/`
- Builds a `branch_map` from decision_id → branch
- Enriches each metadata entry with the `branch` field

Changed `load_metadata()` to call `load_metadata_with_branch()` and return the enriched metadata.

### 2. Regenerated Artifacts

Ran the fixed script, producing updated artifacts in:
